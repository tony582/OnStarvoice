# 独立展示内核（U1，视觉方案待定）

本目录是 StarVoice 新展示层的独立实现，不是现有侧栏文件的搬移或改名。当前包括领域展示模型、分页选择和旧记录快照的只读转换，没有 HTML、CSS、浏览器入口或运行接线。用户于 2026-09-06 将 UIUX 设计交给另一个对话；本批不得将之前的视觉稿固化为新 UI。

基点为 `main@51896d8694c4b19e3731e5b6b7623397420c84a9`，在独立工作目录与分支开发，不依赖 PR #37–#48。客户扩展目录、现有 manifest、sidebar、utils、采集、同步、服务端和数据库均不修改。

## 接口

| 接口 | 用途 | 数据边界 |
| --- | --- | --- |
| `presentResult(summary)` | 单条结果的纯文本展示模型 | 只读摘要及显式采集、同步状态，不读取正文、评论数组 |
| `presentResultDetail(detail)` | 用户打开某条记录后展示详情 | 有界正文与评论，不触发网络、存储、采集或同步 |
| `presentResultPage(summaries, options)` | 结果列表与需处理筛选 | 默认/最多 50 条，分页前按摘要统计；不去重、不更改业务记录 |
| `adaptStoredSummary(record)` | 历史存储形状转换到新摘要 | 不调用旧读取器，不把历史状态当本次确认；另外返回来源说明 |
| `adaptStoredDetail(record)` | 历史存储形状转换到详情 | 显式读取有界内容，输出截断标志，不扫描整个数据池 |

输入是未来适配器提供的**已完成权限校验的规范化摘要**，不是直接把旧数据池对象原样传入。

```js
{
  id: 'record-id',
  title: '内容标题',
  platform: 'xiaohongshu', // 或 douyin、weibo
  kind: 'note', // 或 profile、comments
  author: '作者',
  summary: '可选的轻量摘要',
  likes: 0,
  commentsCount: 0,
  capture: { status: 'completed' },
  delivery: { remote: 'confirmed', local: 'failed' },
  reconciliationRequired: true
}
```

- `delivery` 是展示契约，不是对既有存储字段的新解释。未来适配器必须凭对应执行/记录的证据映射，不能把历史 `synced`、成功数量或 `capture.status` 直接当成服务器和本地双确认。
- 模型只输出文案、数值文本和展示状态，不输出重试、同步、释放挂起或任务成功的执行许可。
- 远端已接收但本地未确认时，保留两阶段差异，不显示为全部成功。未知或矛盾状态不得自动变成成功。
- 输出仍可能包含来自正文的 `<...>` 等普通文本；最终视图必须使用 `textContent` 或框架默认转义，禁止作为 HTML 插入。
- `id` 是精确查询键，不作显示截断或字符替换；无效时为空，详情/动作适配器必须拒绝空键，不得按标题或列表位置猜测身份。文案只作为默认表达，稳定状态键供最终设计的独立术语体系使用。
- `truncated.body/comments` 表示详情预览有裁剪，既不是采集失败，也不证明采集完整；界面必须说明这是部分预览。最多显示 50 条评论，不能把预览长度当作平台评论总量。
- 历史同步 `status` 与实际采集状态不同；note/profile 没有完整采集证据时为 unknown。独立 comments 记录的采集状态仅代表该评论记录，来源说明标记 `captureScope: comment_record`。
- 历史记录适配始终将 remote/local 设为 unknown。其结果是“未核对”，不是推断它们同步失败；视图不得据此自动重试或将其改写为失败。新回执适配器是后续独立工作。
- 分页器只减少返回的展示模型数量，不是持久化层优化；目前仍遍历传入的摘要。未来适配器也必须按摘要/详情分开读取，不能先读完整池再投影，并且要按租户/任务范围提供数据。
- 本批不定义新 UI 入口、导航、颜色和页面排版；不删除业务功能或更改平台采集等待。

## 实现边界检查

`scripts/check-extension-ui-boundary.mjs` 检查本目录源文件的本地依赖、旧代码引用和网络/浏览器副作用。默认模式用于无 UI 入口的核心模块；`--require-ui-entry` 额外要求 HTML 入口及禁止后台连接的预览 CSP。

这是一道静态防回归门禁，不是任意 JavaScript 的安全沙箱、完整相似性检测或权属鉴定。语法混淆、运行时动态行为及未来接线仍需人工审查和隔离测试。现阶段严格入口检查应该失败，因为尚未设计或实现新 UI。

## 设计完成后的接入顺序

1. 在此接口之上实现用户选定的独立视图；视觉层只消费展示模型，不直接读取旧数据池。
2. 连接真正的只读数据来源到本批已有适配器，继续用脱敏 fixture 对照平台类型、缺字段、零评论、部分完成、远端接收/本地失败等场景；不能直接复用会修复 ID 并写回的旧池读取器。
3. 对接任务命令时明确执行身份、取消、进度和确认语义，不让视图自行推导执行权限。
4. 新旧实现隔离对照通过后，才拟定客户包切换与旧渲染链退出清单；接入、合并、发布分别验收。

本批没有替换客户运行中的共同模块，不能据此声称全部代码区分或法律审查已经完成。它交付的是可以被任何选定 UI 使用、无旧渲染依赖的新实现。

## U2：不依赖视觉稿的只读会话

`application/result-read-session.mjs` 新增 `createResultReadSession`，通过可信注入源读取有限摘要页和当前页的精确 ID 详情。`domain/read-contract.mjs` 校验固定 tenant/task/execution 范围、快照、查询和分页一致性；不把响应回声当鉴权。

刷新/取消/关闭会失效旧请求与选择；未来视图即使拿到了已完成结果，也必须在更新前检查 `session.isCurrent(result.requestToken)`。会话既不连接真实存储，也不修改旧运行链路；设计方案尚未定稿，不增加 UI 入口或最终用语。

完整输入/输出、源侧责任、范围与快照要求、未接线边界见 [U2 接入契约](../docs/architecture/extension-u2-scoped-read-session-20260906.md)。本层只保留当前页 ID，不是现有大数组存储的性能修复；不用于直接更新客户包。
