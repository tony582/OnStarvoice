# 无人巡检附带近7天负面巡查：确认方案

版本：v5 · 2026-09-08  
状态：客户已确认业务方向；本文为设计方案，尚未实施。  
本文件替代此前讨论中的30天默认范围、长期跟踪池和历史抽查建议。

## 1. 确认的产品形式

在现有“新建/编辑无人巡检”配置中增加一个勾选项：

**☐ 同时巡查近7天负面内容**

辅助说明：关键词采集有节点空闲后，自动轮流复查前7天的负面内容，并沿用内容处理状态的排除、降频规则。

勾选即随当前无人巡检计划保存，不再要求客户单独创建负面巡查任务。默认不为已有计划自动开启；编辑保存后从下一轮生效。取消勾选只影响以后轮次，当前轮停止沿用明确的停止操作。

勾选后可展示范围说明和候选预估，不要求客户额外填写一套计划。日期口径沿用前文测算的内容发布时间；状态频率等参数放在高级设置，不把复杂分级表放在主流程里。

原有关注内容复查仍可作为独立选项，与负面同帖时合并执行。本次确认的7天范围约束负面模块，不擅自改变人工关注清单的范围。

## 2. 范围：每轮开始前7天

- 按本轮开始时间T，取发布时间位于[T−7天,T)的负面内容，即连续168小时；沿用计划时区进行显示。
- 沿用该计划的平台、关键词/主题范围及租户权限，不从其他客户或无关主题取内容。
- 本轮固定起止时间，不随不同节点的领取时刻漂移；下一轮重新计算窗口，新内容加入、超窗内容退出。
- 不把“最近7天”解释成“近7天入池后再跟踪30天”，也不附加范围外历史抽查。
- 无有效发布时间的内容单列为范围无法确认，不用最近采集时间替代。复查本身不能让旧帖重新变成近7天内容。
- 本轮新采集并判负的内容展示为新增发现，下一轮仍符合范围时才进入复查；完整首次采集不在同一轮立即重复打开。

## 3. 执行：关键词优先，空闲节点接续

1. 每个空闲节点先判断当前是否有兼容且可立即执行的待领关键词，有则继续关键词。
2. 没有可领关键词时，开始领取该平台可执行的负面巡查；其他节点可继续关键词采集，不设置“全部关键词完成后才能巡查”的屏障。
3. 同一节点一次执行一个工作项；完成后再次判断关键词和巡查队列。
4. 关键词在重试冷却或等待人工处理时，兼容巡查可先执行；关键词恢复后，在节点下次空闲时重新优先领取，不中断已经开始的巡查。
5. 若同时勾选关注复查，沿用同帖去重和资源协调；不把所有节点都绑在同一篇帖子上。

## 4. “轮着来”的具体规则

小红书、抖音分别保存轮转进度，候选按帖子身份去重；每次定时启动不重置为“最新帖子从头查”。

在当前窗口、处理状态允许且可执行的集合中：

- 先查尚无正式复查记录的内容，其中最接近窗口下界、即即将出窗的先查。
- 已经查过的内容先判断是否达到其处理状态规定的复查日期；到期后按最久未成功复查的顺序领取。
- 成功并确认入库后，记录本次完成时间、下次到期日，放到对应轮转队列后部；不能因节点仍空闲而立即重查同一篇。
- 失败不视为查过，保留原未完成记录并进入有界冷却，让其他帖子继续。验证、登录问题遵循现有人工恢复规则。
- 没有巡查资格的内容不因“从未查过”获得例外。
- 新一轮超出7天范围时退出负面清单；若此前未查成，保留“窗口内未覆盖、现已超范围”记录，而不是继续访问范围外内容。
- 剩余空闲时间不保证能覆盖全部候选。结果显示未查、即将出窗未查、失败、状态排除等数量，避免把轮转清单建好当作覆盖完成。

## 5. 沿用已有处理状态

状态直接读取现有record_triage.status，不新建一套业务状态。以下具体频率继续保留为可调的建议，客户本次确认的是7天范围和轮转方式，并未额外确认所有数值。

| 现有状态 | 建议处理 |
| --- | --- |
| 待处理 | 正常轮查，建议每日到期 |
| 已回复 | 建议每3天复查 |
| 已复核 | 稳定后降低频率，建议每7天 |
| 已复核-非监控内容 | 默认排除自动巡查 |
| 已不可见 | 暂停常规巡查，保留历史 |
| 负面–隐私设置无法触达 | 仍按普通内容轮查；无法联系不等于内容不可见 |
| 负面-飞书表 | 降低重复跟进频率，建议每3天 |
| 负面-冷处理 | 有稳定证据后降频，建议每7天；可靠升温可加频 |

冷处理等允许巡查的低频状态，首次进入候选时先安排一次复查机会，成功后再进入低频等待，不因“每7天”把首次复查直接推到窗口外。在严格7天窗口内，每7天复查通常意味着只获得一次正式复查机会，应在规则说明中写清楚。

可靠升温或已有高/紧急优先级可提高范围内可巡查内容的频率，但不能越过7天边界、非监控或不可见排除。自动巡查不修改人工处理状态、飞书表号或归档状态。

领取前再次检查人工状态：已改为排除状态的未执行项不再下发，并保存撤出原因。归档继续作为独立属性，是否排除由明确的计划规则决定。

## 6. 运行量与结果展示

以实际合资格候选、状态到期情况和节点空闲时间决定本轮派发量。保留可配置的执行窗口和上限以防积压，但不将之前讨论的“总量50篇/天、抖音30篇、小红书20篇”固化为已确认要求，也不固定70/20/10分配。

计划/本轮详情展示：

- 本轮实际7天起止时间；
- 各平台符合范围的唯一帖子数；
- 本轮首次待查、已到期、暂未到期；
- 已成功、失败、未执行、状态排除、超窗未覆盖；
- 当前轮转位置、每篇最近一次成功复查和下次到期。

正常到期频率按计划时区的日历批次错峰安排，不因上次晚于计划开始时间完成而错过次日批次。同一天多轮共享巡查记录，不能每轮重置后再次全量访问。

负面和关注同帖只访问一次，保留两个业务归属。关键词搜索数量与逐帖复查数量分开统计。

## 7. 实现范围与验收

沿用现有云端计划、运行批次、工作项、执行尝试及兼容节点领取，不增加第二套调度系统。本次新增的是计划勾选字段、7天候选解析、现有处理状态映射、轮转持久状态和结果汇总。

首期必须验证：

1. 勾选后每轮附带负面巡查；不勾选维持原关键词行为。
2. 其他节点仍采关键词时，空闲节点能够领取负面；有兼容待领关键词时优先关键词。
3. 两个平台保存独立进度，跨轮和重启后不反复从同一批开始。
4. 只使用本轮冻结的前7天窗口，下轮按新窗口增减，不自动扩大为30天或历史池。
5. 非监控、已不可见排除；冷处理/飞书表按规则轮查；首次未查不因低频直接等待出窗。
6. 同帖不会被两个节点或负面/关注模块重复执行；失效attempt不能覆盖接续结果。
7. 失败有界恢复且不挡住其他帖子；成功以实际结果入库为准。
8. 暂停计划、停止本轮和取消勾选的含义清楚；既有结果及人工处理状态保留。
9. 窗口内未完成后出窗有记录，不能把未覆盖标为成功。
10. 勾选配置、候选预览、真实节点领取、实际采集与汇总完成整条验收，才能声称功能已实现。
