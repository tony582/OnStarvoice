# 微信「搜一搜 → 文章」采集契约调研

日期：2026-11-09
分支：`codex/research-wechat-articles-20261109`
审查基线：`dcb5d11`（视频号接收人配置、多选转发发布记录之后）

## 范围与结论状态

用户最终选择的入口是微信 **「搜一搜 → 文章」**，不依赖「看一看」。目标是调研公众号文章、图文能否按现有视频号的业务要求采集，并特别处理文章末尾的评论／留言及关闭评论的情况。

本文只记录代码契约审查和建议设计，**不是已实现功能，也不是文章采集真机验收报告**。现有视频号的历史真机结果不能作为文章页面的验证证据；本轮实机观察另行记录。本文中的候选字段、状态和平台名尚未形成正式接口。

现有代码只实现 `wechat_channels`（视频号），没有公众号文章适配器或 `mp.weixin.qq.com` 文章正文解析器。视频号已有 `isImage → noteType: image` 的图文记录，但其页面、作品身份和数据源与公众号文章不同，不能因为都是“图文”就共用同一套页面解析。

## 一、现有视频号基线

### 采集内容与来源

| 项目 | 已存在的契约 | 对文章的意义 |
| --- | --- | --- |
| 搜索列表 | 关键词、名次、文案摘要、作者、时间标签、点赞标签 | 可以复用列表发现与任务关联，文章列表解析必须重新验证 |
| 正文详情 | 描述、作者昵称及头像、精确发布时间、复制的原文分享链接、封面、视频／图文类型 | 文章需要独立标题与全文，不能把搜索摘要当正文 |
| 互动 | 喜欢、推荐、转发、评论总数；另存原始格式数 | 文章的阅读、点赞、在看等名称和含义须按页面核实 |
| 评论 | 作者、地区、时间标签、正文、点赞数、回复标记、父评论索引 | 保留业务字段，改为文章末尾的留言布局和状态判断 |
| 评论范围 | 计划开关，默认 50 条，上限 500 条；已读完与部分采集分开 | 数量限额可以复用，但不能声称可见留言就是平台全部评论 |
| 发布窗口 | 搜索后用详情精确时间复核；超窗不入库 | 文章若只显示日期，应保留日期精度，不伪造到秒的时间 |
| 后续业务 | 通用记录入库、分诊、舆情分析、报表、负面巡查及发到微信 | 新平台需逐处接入；现有视频号支持不代表文章已具备这些能力 |

视频号的详情字段并非全部通过手机识字取得：手机复制 `weixin.qq.com/sph/…` 分享链接，电脑普通浏览器打开公开预览页，解析该页面自身加载的 `feed/get_feed_info` 响应；评论再由手机截图和本机 OCR 读取。当前公开预览解析器只接受视频号短链，不能直接处理文章链接。

当前事件中的文案最多 20,000 字、封面只有单个 URL，没有文章内图片列表、正文段落顺序或正文截断标记。服务端把文案首行截为标题，并无独立文章标题契约。

### 调度、所有权与入库

- 共用现有 `capture_agents`、`capture_tasks`、`capture_task_items`、`capture_task_item_attempts`，没有另建手机任务队列。
- 一个手机进程按平台选择适配器，同一时刻只操作一个任务。主机设备锁、服务端持有状态、租约、停止确认及恢复尝试共同约束手机操作。
- 领取依据节点允许平台、当前就绪平台及功能能力；旧采集器不能领取需要新能力的任务。
- 每次尝试携带任务、工作项、节点、尝试、分配版本、请求摘要等身份。上传必须校验租户、节点、尝试归属及采集时间窗口。
- 手机先持久保存事件，每批上传 1–5 条。服务端保存回执；同事件相同内容重复上传返回原回执，不同内容返回冲突。已在合法尝试期间采得的事件可在任务结束后迟到入库。
- 普通手机任务预算、逐项采集间隔、AI 相关性预筛、运行诊断及未上传事件管理均可复用。页面识别失败不应成为反复无界限点击的理由。

### 现有去重与状态边界

视频号作品 ID 由 `createtime + nickname` 计算；事件 ID 由任务身份与作品身份确定。评论 ID 包括作品、父评论、作者和正文，并在重采时对 OCR 近似结果尝试复用已存 ID。

这些是视频号现有实现，**不是文章身份设计的推荐原样复制**。同一公众号同一天可以发多篇文章，作者昵称和发布时间也不能替代稳定文章标识。

现有评论状态只接受 `captured / partial / disabled / empty / not_relocated`。`disabled` 用于计划未启用评论，当前部分可恢复读取失败路径也沿用该默认值；服务端还会把不认识的状态折回 `disabled`。文章接入前应明确扩展验证和显示逻辑，否则新增 `closed / unknown` 会被静默丢失。

## 二、建议的文章数据契约

### 身份与基本信息

建议新增独立平台，如 `wechat_articles`，显示名称为“微信文章／图文”；最终名称待实现时统一确认。

| 字段组 | 建议保留的信息 | 约束 |
| --- | --- | --- |
| 身份 | 稳定文章 ID、身份来源、原始分享链接、规范链接 | 不用标题或搜索摘要单独作 ID，不把临时分享参数纳入作品身份 |
| 作者 | 公众号名称、可验证的账号标识、作者署名、头像 | 公众号名与署名作者分开；未显示的账号标识留空 |
| 发布时间 | 页面原始文字、解析时间、时区、精度、采集时间 | 只有日期时标 `date`，不补出不存在的时分秒 |
| 内容 | 独立标题、正文纯文本、有序正文块、封面、图片列表 | 标题与正文分别保存；正文不能包含广告、推荐文章、留言输入提示 |
| 来源 | 搜索关键词、结果名次、列表摘要、详情来源、证据引用 | 保持搜索卡片与打开文章的身份绑定 |
| 可用性 | 可访问、明确已删除、访问受限、未知及对应证据 | 搜不到、打不开、登录限制均不能自动断言文章已删除 |

### 正文和图片顺序

建议以有序 `bodyBlocks` 保存正文结构，块类型至少包括文本段落和图片。图片块引用 `images` 中的同一项，保留其在正文中的位置；同图重复出现是否合并文件可另行处理，不能丢失出现位置。

图片记录建议包含：正文顺序、页面可见来源 URL、原始 URL（若页面正常提供）、说明文字、宽高（若可得）、获取状态和证据来源。只拿到 URL 不等于已下载、已存储原图或可长期回放，应分别记录这些结果。

图片内文字识别若纳入舆情检索，应独立保存 OCR 文本、对应图片和识别状态，避免把 OCR 内容冒充页面原生正文。图文中的嵌入视频、音频、卡片等也应保留块类型和占位信息，不把未抓取媒体误称为完整采集。

正文完整性建议单独记录：`complete / partial / unavailable`，并带截断原因、已见结束标记和采集范围。文章可能超过视频号现有 20,000 字限制，不能继续静默截断后标记 `detailCaptureStatus: done`。实现时需决定合理上限与超限行为，而不是承诺无限长度。

### 互动数据：未知不等于零

按实机页面分别识别阅读、点赞、在看、转发、评论／留言等指标；只保存实际可见或正常页面明确给出的值。

- 未显示、未加载、需要其他权限或无法可靠识别：值为 `null`，附原始标签和原因。
- 页面明确显示 0：可以保存 0。
- 页面显示“10万+”等区间：保留原文和下界语义，不能当作精确 100,000。
- 没有转发数、收藏数时，不为迎合现有表格填 0。
- 不把文章“在看”未经核实映射成收藏，不照搬视频号“喜欢／推荐”的映射。

这需要检查通用记录层及前端当前的数值默认值；本文提出的是目标契约，不声称现有所有页面已能区别 `null` 与 0。

## 三、文章末尾的评论／留言

### 必须先确认正文末尾

评论读取前，应证明已到达目标文章的正文末尾或已定位到该文章的留言区。正文滑动、广告区、推荐文章和留言区需要各自可验证的锚点。

达到翻页、时长、字数预算，或连续两屏变化很小，都不能单独证明“文章没有评论”。长文章、图片懒加载和网络等待可能造成停滞，应保留证据并标为未确认或部分完成。

### 状态含义

以下是建议语义，具体字段可在实现时拆为可用性和采集结果，但这些情况必须能独立表达：

| 状态 | 含义 | 可以据此断言什么 |
| --- | --- | --- |
| `disabled` | 采集计划没有要求读取评论 | 没有执行评论采集；不能断言作者关闭或评论为 0 |
| `closed` | 页面明确显示评论／留言功能关闭或不可发表 | 仅确认页面表达的关闭状态；保存提示原文和位置 |
| `empty` | 已验证留言区域，并看到明确暂无留言／零条等证据 | 当前可见留言为空；不推断后台或未公开留言为空 |
| `unknown` | 没确认到末尾、没定位到留言区或提示语义不明确 | 无法判断，数量保持 `null` |
| `captured` | 已采得可见留言，且观察到可见范围的结束证据 | 本次可见范围已读完，不等于平台全部评论已取得 |
| `partial` | 采得部分留言后达到限额／预算，或仍有未展开回复 | 允许保留已采内容，同时说明未完成范围 |

关闭“发表新留言”不一定等于历史留言不可读。若页面同时显示旧留言，应照常采集可见内容，并单独保存 `postingState: closed` 一类状态；不能因看到“关闭”就把已有留言清空。

若页面区分精选留言、全部可见留言、作者回复等范围，应保留 `visibilityScope` 或对应原文。这里只采正常页面可见内容，不承诺未公开、删除、折叠未展开或审核中的留言。

每条留言沿用作者、正文、时间、地区（页面存在时）、点赞、回复和父子关系，并记录所用来源。没有显示的时间、地区、点赞都留 `null` 或明确缺失，不从相邻评论推补。只有作者回复不代表只有一层，回复关联须按实际展开结构确认。

## 四、稳定文章 ID 和重采去重

先验证普通分享／复制得到的文章链接，以及文章页面公开提供的身份字段，再确定规范化规则。若实测链接包含账号、消息和文章序号等稳定部分（例如候选 `__biz / mid / idx`），必须先验证同文章多次复制、不同搜索入口、同消息多篇文章的表现；不能仅凭字段名认定稳定。

建议原则：

1. 文章 ID 与分享追踪参数、临时校验参数、搜索来源、当前关键词无关；保留原始 URL 供审计。
2. 同文章被多个关键词发现、再次巡查或再次复制分享链接，更新同一租户中的同一记录，同时保留新的采集观测。
3. 同公众号同日不同文章、同标题不同文章、同一消息中的不同图文不得合并。作者昵称改名也不应使同一稳定文章变成新作品。
4. 未取得可验证稳定身份时，标注身份未确认并限制自动合并，不能伪造精确身份。
5. 若正常页面暴露留言 ID，优先使用；否则以文章身份、作者／正文、父级和可见时间等证据构造替代身份。OCR 模糊匹配只作为受限兜底，避免把同一用户两条相同留言无条件合并。
6. 本地事件 ID 仍绑定任务尝试与文章身份；重采产生新观测，网络重传沿用原事件和原负载。

## 五、复用范围与需要修改的模块

| 领域 | 可以复用 | 必须新增或改造 |
| --- | --- | --- |
| 手机基础能力 | ADB 截图／点击、中文输入、剪贴板读取、本机 OCR、设备互斥 | 搜一搜文章入口、搜索筛选、结果卡片、文章页面、末尾留言区的版本化适配 |
| 内容读取 | 普通页面打开、解析器错误分型、证据保存方式 | 文章解析器、正文与图片顺序、长文章完整性、访问状态；不能复用视频号 feed 接口 |
| 调度 | 原任务队列、租约、预算、停止恢复、节点锁 | 新平台／工作流、就绪能力、兼容版本门槛；不能向旧版采集器派文章任务 |
| 上传 | 持久事件、批次回执、历史尝试归属校验、幂等重传 | 文章事件验证、长度限制、独立身份、评论新增状态、缺失指标语义 |
| 入库 | 通用记录和评论保存、观测归属、租户隔离 | 平台白名单、正文块／媒体字段、稳定去重、未知值和部分完成的传播 |
| 管理后台 | 任务、详情、分诊、筛选的现有框架 | 平台显示、文章类型、正文／图片展示、阅读／在看指标、评论关闭和未知状态 |
| 后续业务 | AI 相关性、舆情分析、报表及巡查框架 | 文章平台接入、长文输入策略、原文找回／删除证据、文章分享路径 |

主要代码位置（相对仓库根目录）：

- `runners/android/src/device/wechat-profile.mjs`、`wechat-adapter.mjs`、`wechat-flow.mjs`：当前配置固定为视频号页面和已校准版本。
- `runners/android/src/device/wechat-comment-reader.mjs`、`wechat-comments-parse.mjs`：当前解析的是视频号评论弹层，不能直接用于文章末尾留言。
- `runners/android/src/preview/share-preview.mjs`：目前只接受视频号短链和预览响应。
- `runners/android/src/core/wechat-runner.mjs`、`wechat-evidence.mjs`、`wechat-patrol.mjs`：任务平台、事件、内容与巡查身份耦合于视频号。
- `runners/android/src/daemon/multi-device.mjs`、`task-runner.mjs`：增加文章适配器路由和就绪能力，同时保留单设备串行操作。
- `server/services/android-control/mobile-tasks.js`、`validation.js`、`leases.js`、`registration.js`：平台、工作流、任务形状与领取门槛。
- `server/services/android-control/posts.js`、`post-ingest.js`：链接校验、详情必填字段、状态枚举、作品与评论去重、回执和通用同步。
- `server/db/migrations/094_wechat_channels_mobile.sql`：现有回执表的 `platform` 约束只允许 `wechat_channels`；新增平台必须通过新迁移扩展，不能改已发布迁移文件。
- `server/services/capture-orchestration.js`、`capture-orchestration-scheduler.js`、`server/routes/capture-orchestrations.js`：手动、固定批次和弹性调度保持同一平台映射。
- `server/services/relevance-prefilter.js`、`capture-publish-window.js`、`unattended-negative-patrol.js` 以及分析／报表平台枚举：将文章纳入现有业务流程。
- `web/admin/src/pages/dispatch/cloud-tasks/`、`web/admin/src/components/shared/RecordDrawer.tsx` 和数据／分诊／舆情页面：平台与字段展示。
- `server/services/android-control/forward.js` 及手机转发流程：现有只允许视频号，文章转发需独立验证；视频号 `openFinderFeed` 深链不适用于公众号文章。

建议为文章增加独立事件种类和明确协议版本，或在现有上传接口内按平台严格分流。不能仅放宽链接正则，就把文章正文塞进视频号 `preview` 结构。服务器平台必须从授权的任务／尝试校验，不信任手机自行声明平台或租户。

## 六、进入实现前的验收样本

至少覆盖：普通长文章、多图图文、明确有留言、明确无留言、明确关闭留言、旧留言仍可见但不可新发表、需展开作者回复、正文未加载完、文章失效／访问受限、正文超过当前上限、互动数缺失、同文章重复复制链接、同消息多篇图文以及搜索返回恢复。

每类样本应保留正常页面的观察证据和解析输出，并明确哪些字段可得、哪些为 `null`、正文和评论分别是否完整。再用样本建立解析测试；服务端采用隔离数据库验证租户、平台归属、幂等重传、不同关键词重采去重和评论状态保存。真机跑通、自动测试通过、生产部署与业务验收分别记录，不能相互替代。

本轮契约建议未修改采集器、服务端、数据库或生产配置，未新增生产任务。
