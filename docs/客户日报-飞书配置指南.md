# 客户日报：飞书配置指南

核实日期：2026年9月8日。适用于本次客户日报功能。

沿用现有「文档写入助手」（应用 ID：`cli_aa14eef7a038dcd0`），不需要重新创建应用。系统部署、飞书应用配置、客户实际编辑验收是三个步骤；部署完成后，尚未指定接收群、专用目录和编辑者的客户不会自动开始群发。旧首尔报告不作为本次日报目标，也不用于写入测试。

## 1. 先确定接收群和编辑人员

确认以下三项即可，标识提取和服务端配置可由我方协助：

- **发到哪个现有群**：提供准确群名，并在群设置中复制群 ID。
- **谁可以编辑**：指定客户经办人，或明确允许全体成员编辑的协作群。编辑协作群与接收通知的领导群可以不同。
- **日报放在哪里、每天几点发送**：确定专用目录名称和管理人，以及北京时间的发送时间。

飞书 7.60 及以上版本支持群成员在群右上角菜单进入群设置，查看并复制群 ID，通常以 `oc_` 开头。找不到时，我方可在机器人入群后协助只读查询，不需要客户操作 API。[官方群 ID 获取说明](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/chat-id-description)

## 2. 给现有应用补齐权限并发布

由我方应用管理员在[飞书开发者后台](https://open.feishu.cn/app)打开「文档写入助手」，进入**权限管理**，核对下表；已有权限无需重复申请，不要删除原有业务所需权限。

| 用途 | 需核对的权限名称与标识 |
| --- | --- |
| 创建、编辑及读取日报；检查文档分享和留存设置 | 创建及编辑新版文档 `docx:document` |
| 为日报添加指定协作者 | 添加云文档协作者 `docs:permission.member:create` |
| 检查指定协作者是否仍可编辑 | 查看云文档的协作者列表 `docs:permission.member:retrieve` |
| 将已有只读协作者调整为可编辑 | 更新云文档协作者权限 `docs:permission.member:update` |
| 用现有应用机器人发群消息 | 以应用的身份发消息 `im:message:send_as_bot` |
| 首次由应用建立专用日报目录 | 创建云空间文件夹 `space:folder:create` |

这是按当前接口选取的较小权限组合；已有其他官方认可的等效权限也可满足接口。`docx:document` 已覆盖本功能使用的新版文档权限设置查询，无需为该查询额外申请完整云空间管理权限。若改用群自定义机器人通知，群通知本身不需要应用消息权限。获取群 ID 优先使用客户端，也不必为此额外申请通讯录或群消息读取权限。

权限依据：[创建新版文档](https://open.feishu.cn/document/server-docs/docs/docs/docx-v1/document/create)、[批量创建正文块](https://open.feishu.cn/document/ukTMukTMukTM/uUDN04SN0QjL1QDN/document-docx/docx-v1/document-block-descendant/create)、[添加协作者](https://open.feishu.cn/document/server-docs/docs/permission/permission-member/create)、[读取协作者](https://open.feishu.cn/document/server-docs/docs/permission/permission-member/list)、[更新协作者](https://open.feishu.cn/document/server-docs/docs/permission/permission-member/update)、[查询权限设置 V2](https://open.feishu.cn/document/ukTMukTMukTM/uIzNzUjLyczM14iM3MTN/drive-v2/permission-public/get)、[发送消息](https://open.feishu.cn/document/server-docs/im-v1/message/create)。

如使用我方应用向现有客户外部群发送：

1. 在应用的**应用能力**中确认已启用**机器人**。
2. 进入**应用发布 → 版本管理与发布 → 创建版本**。
3. 在**对外共享**中勾选**允许机器人被添加到外部群中使用**。群日报不要求同时开启外部用户单聊。
4. 在**可用范围**中包含负责把机器人加入客户群的我方人员。
5. 保存并**申请线上发布**，等待所需审核完成。

开关置灰时按页面要求完成企业/团队认证或个人实名认证；关联组织应用共享与此开关存在兼容限制，应由应用管理员核对。不能只保存未发布的版本。[官方对外共享操作及限制](https://open.feishu.cn/document/develop-robots/add-bot-to-external-group)

## 3. 把机器人加入现有客户群

由**属于我方应用所在组织、在应用可用范围内、并有目标群操作权限**的人员，在现有客户外部群中打开**右上角菜单 → 设置 → 群机器人 → 添加机器人**，搜索并添加「文档写入助手」。客户组织的外部成员不能代替我方人员添加这款对外共享应用机器人。机器人还需有群发言权限。[官方入群要求](https://open.feishu.cn/document/develop-robots/add-bot-to-external-group)

如果接收的是**客户内部领导群，我方不在群中**，它不会仅因双方跨组织就自动变成外部群。可以由客户有权限的群成员在该群添加**自定义机器人**，进入其**安全设置 → 签名校验**并保存。将机器人地址和签名密钥通过 StarVoice 管理员配置页或双方约定的受控方式录入，不粘贴到普通聊天。该方式仅负责通知，仍需另行完成文档访问权限。[官方自定义机器人设置](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)

## 4. 由我方建立应用专用日报目录，再配置客户协作

当前服务使用应用身份创建文档。飞书明确要求：创建新版文档时指定的文件夹必须由该应用创建。因此，**专用日报目录由我方用现有应用建立**，用户无需自己调用接口，也不要直接把任意个人文件夹链接当成可用目录。

我方可先在应用空间建立独立日报目录，再让指定的我方管理人管理和分享；若希望放在已有大目录内，应先解决应用对父目录的管理权限，再由应用新建其专用子目录。官方说明，给应用授予现有文件夹权限需通过包含该应用机器人的群协作者；直接把应用添加为文件夹协作者并不产生实际权限。具体创建、取得目录标识与录入由我方处理。[创建文档的目录限制](https://open.feishu.cn/document/server-docs/docs/docs/docx-v1/document/create)、[新建文件夹](https://open.feishu.cn/document/server-docs/docs/drive-v1/folder/create_folder)、[给应用开通文件夹权限](https://open.feishu.cn/document/uAjLw4CM/ugTN1YjL4UTN24CO1UjN/trouble-shooting/how-to-add-permissions-to-app)

拿到新目录链接后，由有管理权限的人打开**分享 → 权限设置**：

- 允许这份客户日报内容分享到组织外。
- 在协作者中仅添加双方明确约定的客户成员或协作群，按分工设为可编辑；如选整个群，该群成员会获得相应编辑权限。
- 将复制内容、创建副本、打印和下载允许范围设置为至少包含有编辑权限的客户。
- 链接分享保持关闭或双方认可的受限范围，不设置为互联网上任何人可阅读或编辑。

文件夹内新文件默认继承协作者和权限设置；但单篇文档若独立修改了协作者、对外分享或其他权限，可能中断相应继承。实际还受双方组织策略约束。因此不能只验证目录或一篇旧文档就开启自动发送。[文件夹权限与继承规则](https://www.feishu.cn/hc/zh-CN/articles/360049067444)、[组织的文档分享与留存默认权限](https://www.feishu.cn/hc/zh-CN/articles/265017155035)

**外部编辑者的选择：**页面支持客户邮箱、客户成员标识、协作群标识。优先验证双方已确认可全员编辑、且已加入「文档写入助手」的客户协作群，填为**协作群标识**。添加群协作者时应用必须在该群内。外部共享机器人对非消息/群接口传入外部用户 ID 有限制，不能承诺填一个外部邮箱或 Open ID 就能自动授权成功；邮箱还需对应真实飞书账号并满足联系人可见性。单个客户编辑者可由有权限的管理人先通过目录邀请，再验证新日报能否继承且被系统确认。继承、群授权在本项目中的实际可用性均以第6步验收为准。[协作者可见性要求](https://open.feishu.cn/document/server-docs/docs/permission/permission-member/create)、[外部用户 API 限制](https://open.feishu.cn/document/develop-robots/add-bot-to-external-group)

## 5. 我方录入 StarVoice 配置

进入客户日报页面，展开**飞书接入与自动发送**：

| 页面字段 | 填写内容 |
| --- | --- |
| 应用 ID | `cli_aa14eef7a038dcd0` |
| 应用密钥 | 沿用现有应用密钥，由我方安全录入生产配置；已配置时留空保留 |
| 日报目录标识 | 第4步取得的应用专用目录标识，由我方填写 |
| 飞书文档域名 | 新日报实际所属组织的 `https://……feishu.cn` 域名，不是旧首尔文档链接 |
| 客户编辑者类型 / 标识 | 第4步明确的客户成员或编辑协作群 |
| 通知方式 | 应用机器人，或客户领导群的群自定义机器人 |
| 目标群名称 / 标识 | 实际接收通知的群名和群 ID；应用机器人必须已在群内 |
| 群机器人地址 / 签名密钥 | 仅自定义机器人通知时填写 |
| 客户账号已验证 | 完成第6步后再勾选 |
| 每天自动发送前一天日报 | 初次配置先关闭，验收和首次手动发送完成后再开启 |

生产密钥加密配置、服务端连接、目录及标识提取由我方处理。本机已有连接记录不等于生产服务器已经连接。用户无需重新把现有应用密钥发到聊天；客户组织管理员的审批、飞书个人实名认证及客户账号编辑操作须由相应人员完成。

## 6. 连续验证两份新文档，然后启用每日发送

1. 保存配置，暂不勾选客户已验证、暂不开自动发送。
2. 在日报页面生成一份新版本，点击**生成飞书文档**。此操作不发群消息。
3. 用客户真实账号打开新文档，修改一处正文和汇总表空白格，关闭再打开确认保存；按约定下载或创建可编辑副本。若领导与编辑者权限不同，再由领导账号验证可阅读。
4. 在相同目录、相同设置下再生成第二份新版本并创建飞书文档。保持第一份客户修改，验证第二份也能由客户打开、编辑、保存和留存，确认无需每天补授权。
5. 验证通过后，在配置中勾选**已用客户账号验证**并保存。选择双方确认的版本，点击**发送到飞书群**，核对准确目标群、文档链接及发送成功状态。
6. 最后开启**每天自动发送前一天日报**，设置北京时间并保存。系统从下一次计划时间开始；可在页面查看下次执行时间及最近自动执行情况。

如系统显示「结果待确认」，先由我方核对实际文档或群消息，不连续点击重发。已经交付的文档与客户修改会保留，更正版单独生成。

## 7. 权限不通过时怎样处理

| 现象 | 下一步 |
| --- | --- |
| 搜不到应用机器人、无法加入外部群 | 我方核对新版本发布、对外共享、认证、操作人员所属组织及应用可用范围；群管理人核对群权限 |
| 客户能打开但不能编辑、保存或留存 | 目录管理人核对精确协作者及分享、复制、下载设置；如被组织策略禁止，由相应组织管理员处理 |
| 第一份可编辑，第二份仍需人工加权限 | 继承或系统权限核验尚未闭环，不开启自动发送；由我方继续排查，不能将每天人工补授权称为自动完成 |
| 客户禁止编辑外部组织文档，或要求文件直接归客户组织 | 由客户管理员提供客户组织已有、认可的写入应用和专用目录，我方接入同一日报功能；若暂时无法提供，先使用页面和可编辑 Excel 交付，由客户保存/导入 |
| 客户内部领导群无法加入我方应用 | 由客户配置该群的签名自定义机器人；若组织策略也不允许，则由客户审批认可的消息通道 |

给客户编辑权限与将文件所有权转到客户组织是不同事情。官方文件夹权限说明不支持将文件夹所有权转给组织外用户；客户需要独立持有时，应采用客户组织内写入或客户留存副本的方式。[官方所有权与文件夹权限说明](https://www.feishu.cn/hc/zh-CN/articles/360049067444)

以上是配置指引与官方能力核实，未宣称已完成实际目录、跨组织编辑或群发送验收。
