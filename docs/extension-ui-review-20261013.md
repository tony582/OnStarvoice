实施开始：2026-10-13；验收包完成：2026-10-14。基于企业版 StarVoice `b477e806cd619a6b2b4de47f449f053bfbba5708`、Extension 0.4.23。不是 StarVoice Cloud。

## 当前结论

界面实现、隔离浏览器验收和候选包已完成；**未安装、未重载、未发布到任何采集节点**。真实采集闭环与节点 CPU/内存验收尚未执行，须在一台空闲测试节点通过后再扩大范围。

安装候选包不代表开启新版：**旧界面仍是默认；每个浏览器配置文件单独选择新版。** 这避免了统一发布后所有节点立即切换界面。扩展安装/更新本身仍可能重载后台，因此不能在正在采集或有未落盘数据的节点上更新。

## 兼容机制

1. 入口仍是同一个 `sidebar/sidebar.html`；只有一份原采集逻辑和原状态模块，没有新旧两套引擎。
2. 右上角菜单 → **试用新版界面**。选择只存在本浏览器配置文件的 Extension 本地存储，不写租户配置，也不使用 Chrome 同步存储。
3. 新版通过移动原控件和样式覆盖实现。没有克隆采集按钮、改字段默认值、初始化时触发业务 change、重建结果数据或迁移存储。
4. 新版底部 **设置 → 切回经典界面**。恢复原控件位置、右上角菜单与平台位置并卸载新增样式/订阅，不刷新页面、不重载扩展、不清缓存，也不停止当前采集。
5. 新版模块或样式加载失败时保留经典界面。该回退不是对任意未知故障的绝对保证，完整回退包仍单独保留。

## 性能边界

没有新增轮询、心跳、网络请求、DOM 观察器、UI 框架、远程字体或动画。关闭侧栏时不会加载新增界面层；旧界面只增加约 4.2 KB 的可选模式入口，新版其余 JS/CSS 按需加载。运行状态复用既有三种状态通知，切回时解除订阅；弹窗不再增加背景模糊成本。

这些是代码与隔离测试证据，**不等于已经证明所有节点上 CPU/内存为零增量**。节点型号、浏览器和大结果池渲染仍需真实对照测试。

## 单节点灰度验收

只选择一台空闲、允许测试的节点；其余节点不动。不要从新目录并行加载第二份 Extension，否则可能产生新的扩展身份、授权绑定或 Agent，不能当成原节点更新。

1. 确认没有运行中任务、待同步结果或离线待发送数据；保留原扩展目录和节点授权/配置备份。不要清空浏览器数据。
2. 在该节点按现有发布方式更新候选文件，保持原扩展身份。候选仍为 0.4.23，尚未升级版本号或注册自动更新发布；如需要正式自动分发，验收后另行制作带版本号的发布包。
3. 保持默认经典界面，先验证授权、设备身份、任务连接和一条原有采集/同步闭环。
4. 手动开启新版，在三类采集页各做一组小规模受控任务，检查页面识别、筛选、增强、评论、博主指标、导出、同步和后台记录。监控/无人值守需使用明确允许的测试账号/计划，不向生产批量派发。
5. 检查运行面板停止、隐藏、恢复和异常提示；在允许的受控任务中切回经典界面，确认任务身份与已保存结果持续，不出现重复任务。
6. 同平台、同参数、同结果池规模比较经典/新版的空闲、运行、结果滚动场景；记录浏览器任务管理器 CPU、内存、响应和原有业务回执。若有持续明显增量、卡顿、丢控件或同步差异，停在该节点，不扩大发布。
7. 首台通过后再按小批次扩展；新版仍由每个节点主动开启，不做全局强制切换。

## 回退顺序

**优先 UI 回退：**新版底部设置 → 切回经典界面。运行面板全屏时先用原来的“隐藏”，再打开设置。此操作本身不卸载/重启扩展。

**完整文件回退：**仅当 UI 回退不可用或确需退回旧包时，在节点空闲、结果安全保存后使用经典回退包恢复原扩展目录，再按现有方式重载。重载会影响正在工作的扩展，因此不能当成运行中无损回退。不要卸载扩展、清空存储或更换扩展身份来回退。
