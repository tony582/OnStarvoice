## 1. 本批边界

本批只处理 G3 审计指出的唯一 Cron → Route 业务反向依赖：

```text
server/cron.js
  → server/routes/capture-orchestrations.js
    → reconcilePendingOrchestrationRetries
```

目标结构为：

```text
server/cron.js
  → capture/infrastructure/postgres-pending-orchestration-retry.js
    → capture/application/pending-orchestration-retry.js

server/routes/capture-orchestrations.js
  → application policy + PostgreSQL adapter
  → 仅保留旧 named export 的兼容转发
```

没有修改 API、请求或响应 shape、数据库 schema、迁移、进程角色、生产配置、Extension 源码/版本/构建交付物，也没有部署、生产数据操作或实际 split。PR #29 不在本批范围内。

## 2. 实施内容

### 2.1 Application 用例与纯策略

新增 `server/modules/capture/application/pending-orchestration-retry.js`：

- 用显式 `withTransaction` 与 `dispatchOnePendingRetry` 端口编排有界串行扫描；
- 保持 `1–100` limit、逐候选独立事务、等待项 exclusion、失败隔离和原 summary shape；
- 集中保存 retry lineage 校验、确定性 UUID、Agent 兼容性、平台安全与 stale marker 策略；
- 不依赖 Express、Router 或 HTTP 请求对象。

### 2.2 PostgreSQL adapter

新增 `server/modules/capture/infrastructure/postgres-pending-orchestration-retry.js`：

- 承接候选查询、上海当日用量 fail-closed、Agent slot/advisory lock、事务与 SQL；
- 保持 Agent → source execution → parent → item 的既有锁顺序；
- 保持 stale marker CAS、父任务聚合、确定性 child/Command/Attempt、事件投影和幂等语义；
- 导出 canonical `reconcilePendingOrchestrationRetries`，由 Application 工厂绑定 PostgreSQL 端口；
- 其完整相对依赖图不经过 `server/routes/`，也不依赖 Express。

### 2.3 Cron 与兼容入口

- `server/cron.js` 改为直接导入 canonical PostgreSQL adapter；
- `server/routes/capture-orchestrations.js` 删除约 1,500 行已迁移的扫描、策略、SQL 与事务实现；
- 路由仍兼容转发旧 named export，已有内部调用方不需要一次性改路径；
- 真实 PostgreSQL 集成测试改为直接导入 canonical adapter，避免测试继续把路由误当业务所有者。

## 3. 行为不变量

本批保持以下不变量：

1. `retryPending` 仅处理已结算 source execution、非终态/非模板/非 unattended plan 的父任务；
2. 未知上海当日用量、超出账号限额、Agent 能力或授权不足均 fail closed；
3. 同一 Agent 的 execution slot、活动任务与 Command 仍共同阻止重复下发；
4. lineage 继续校验 request key/hash、plan hash、source execution、parent/item revision 与 attempt count；
5. stale marker 仍使用完整 marker snapshot CAS，不能覆盖并发刷新；
6. child task、Command 与 Attempt ID 仍按相同输入确定性生成；
7. item CAS、Attempt 先于 Command、父任务 revision CAS 和事件投影顺序不变；
8. 等待 Agent、stale、invalidated、failed 与 dispatched 的 summary 字段和计数语义不变。
