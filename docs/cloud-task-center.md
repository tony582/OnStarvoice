# 云端采集任务中心

> 稳定版基线：Extension `0.3.73`，数据库迁移至 `054_restore_iso_publish_timestamps.sql`。
> 本文说明调度中心的产品边界、Agent 模型、任务生命周期和恢复原则。字段与接口以 [API 接口文档](./API接口文档.md) 为准，完整状态转换以 [任务编排与状态模型](./任务编排与状态模型.md) 为准。
>
> 调度中心当前仍标记为 Beta。已有链路可以用于受控生产，但多 Agent 接力、无人值守、新任务类型和平台页面变化必须在目标客户环境完成验收；不得把“稳定基线”理解为对所有账号、页面和风控场景的无条件承诺。

## 1. 系统解决什么问题

云端任务中心把“任务定义、分配、状态、恢复和审计”放到云端，把真正依赖平台登录态的页面操作留在客户浏览器：

- 后台统一查看每个浏览器 Agent 是否在线、正在执行什么、排队多少以及最后业务进展。
- 一项包含多个关键词的任务可以拆成互不重叠的工作项，分配给多个 Agent 并行执行。
- Agent 离线时任务保留在云端队列，上线后领取；Agent 遇到可接力故障时可把剩余工作交给空闲 Agent。
- 节假日或无人值守期间，运营人员可以远程继续、中止、清理或重分配任务。
- Extension 与后台显示同一任务的状态，避免“后台在跑、Extension 不知道”或“本地已结束、云端仍执行中”。
- 一次性任务、无人值守计划、负面帖子巡查和官方账号评论巡查共用同一调度底座。

它不是云端爬虫，也不迁移浏览器 Cookie。平台访问仍发生在绑定 Agent 的浏览器中，使用该 Profile 自己的小红书、抖音等登录状态。

## 2. 设备、浏览器与 Agent

### 2.1 三个概念

| 概念 | 含义 | 调度意义 |
| --- | --- | --- |
| 物理设备 | 一台电脑，主要用于运营识别和归组 | 不直接执行任务 |
| 浏览器 Profile | 一份独立的 Chrome/Edge 用户目录及登录态 | 一个独立执行环境 |
| Agent | Extension 在一个浏览器 Profile 中注册的云端节点 | 云端分配任务的最小单位 |

因此：

- 一台电脑可以运行多个 Agent，例如 Chrome 负责小红书、Edge 负责抖音。
- 同一浏览器 Profile 的多个窗口共享 Extension 存储、登录态和采集锁，不能当成多个 Agent。
- 如果需要最大化并行，应使用多个独立 Profile 或不同浏览器，并为每个 Profile 安装、激活 Extension。
- Agent 显示名称是给客户识别的业务名称；短 ID 只用于诊断，日常界面应弱化。
- 激活码的环境绑定数量必须覆盖计划使用的 Agent 数量。

### 2.2 在线不等于可执行

Extension 默认每分钟上报心跳，两分钟无心跳视为离线。绿色“在线”只证明 Extension 最近联系过服务端，不代表：

- 平台账号仍登录；
- 当前页面可访问；
- 调试会话已建立；
- 没有验证码、风控或弹窗；
- 本地采集锁空闲；
- 当前任务仍有真实业务进展。

诊断时必须同时查看：

1. **设备心跳**：Extension 是否在线；
2. **任务心跳**：任务循环是否仍存活；
3. **业务进展**：关键词、作品、评论或增强数量是否推进。

## 3. 总体执行链路

1. Extension 完成激活并注册 Agent，服务端签发只属于该 Agent 的随机令牌；数据库仅保存令牌哈希。
2. 后台创建一次性任务或无人值守计划，并明确执行方式、业务配置和候选 Agent。
3. 多 Agent 任务先拆成工作项，再按确定性规则进行连续、均衡且不重叠的分配。
4. 服务端创建云端任务、工作项、命令和审计事件；在线 Agent 拉取命令，离线 Agent 的命令保留等待上线。
5. Agent 领取命令后创建本地任务账本，再通过心跳持续镜像状态、检查点、统计和真实业务事件。
6. 任务完成、部分完成、失败、需要人工处理或中止后，服务端根据工作项终态汇总父任务，不能仅凭进度条 `100%` 推断成功。
7. 恢复时以最近有效检查点继续未完成项；不会迁移正在运行的浏览器页面，也不会重复提交已完成工作项。

## 4. 多 Agent 编排

### 4.1 当前约束

- 单个编排最多 `300` 个关键词。
- 单次最多选择 `50` 个 Agent。
- 系统生成连续、互斥的关键词切片，任意两个 Agent 的工作项数量差不超过 `1`。
- 没有工作项的 Agent 不生成空任务。
- 当前每个工作项默认最多执行 `1` 轮；失败后的再次执行由重试或重分配产生新的尝试。

例如 20 个关键词分给 4 个 Agent 时，每个 Agent 获得 5 个；其中一个 Agent 需要人工处理时，其未完成工作项可以重新分配给空闲 Agent，而已完成项不会重复执行。

### 4.2 手动分配与系统建议

调度台必须同时支持：

- **手动分配**：运营人员逐项指定 Agent，适合账号分工、指定设备或风险隔离。
- **规则建议**：优先空闲、平台匹配、在线且负载较低的 Agent。
- **接力建议**：原 Agent 离线、遇到风控或持续无业务进展时，建议把未完成项交给其他 Agent。

系统建议不能越过这些硬条件：

- Agent 属于当前租户；
- Agent 未停用、未退役；
- Agent 声明支持目标平台和任务能力；
- 目标平台账号与浏览器登录态由运营负责确认；
- 涉及验证码或账号安全风险时必须人工确认，不能自动换机反复试探。

## 5. 一次性任务与无人值守计划

### 5.1 一次性任务

创建后立即进入云端队列：

- Agent 在线且空闲：领取并执行；
- Agent 在线但忙碌：进入本地或云端排队；
- Agent 离线：显示“等待设备”，上线后领取；
- 后台或 Extension 可中止，已采结果保留。

一次性任务不会覆盖 Agent 已保存的无人值守计划。

### 5.2 无人值守计划

保存计划只更新计划镜像，不应立即产生一次采集。到达运行时间后才创建真实业务任务。

当前计划支持：

- 每天运行；
- 指定日期运行；
- 时区固定为 `Asia/Shanghai`；
- 最多保存 `400` 个指定日期；
- 可配置最多 `240` 分钟随机延迟；
- 计划重叠时跳过重复触发；
- 默认允许 `360` 分钟迟到宽限；
- 指定日期已经全部结束且无后续日期时，计划应显示“已结束/无后续排期”，而不是永久“已启用”。

计划配置与每次真实运行必须分开记录。任务列表展示业务运行，计划页展示计划本身，不能为每次心跳或同步生成无业务价值的“数据同步任务”。

## 6. 本地账本与云端镜像

Extension 本地账本是浏览器执行过程的事实来源，云端是跨设备管理和审计镜像：

- 活跃任务超时阈值默认约 `10` 分钟；
- 终态任务保留约 `30` 天，最多约 `300` 条；
- 单任务保留最近约 `50` 个事件、`500` 条关键词结果；
- 检查点包含当前轮次、当前关键词、完成/失败/跳过项、结果和人工介入信息；
- 云端快照只追加，不覆盖历史；
- 相同指纹的重复快照幂等去重。

每次执行尝试都带有尝试编号和执行标识，进度写入还带单调递增的 `progressSeq`。服务端必须拒绝：

- 旧尝试覆盖新尝试；
- 更小进度序号覆盖更大序号；
- 终态任务被迟到的“运行中”心跳复活；
- 目标作品不匹配时把采集结果写给另一工作项。

## 7. 状态分层

### 7.1 Agent

- 在线
- 离线
- 停用
- 已退役

离线 Agent 可以保留待领取任务；停用或退役 Agent 不应再领取新任务。永久不再使用的节点应退役或删除，避免队列永远等待。

### 7.2 云端任务

- 等待设备
- 待领取
- 运行中
- 需要处理
- 已完成
- 部分完成
- 执行失败
- 已中止

### 7.3 Agent 命令

- 待领取
- 已领取
- 执行中
- 成功
- 失败
- 已过期

### 7.4 工作项

- 等待
- 执行中
- 待重试
- 成功
- 已跳过
- 失败
- 需人工处理

父任务的“完成/部分完成/失败”必须由工作项结果聚合，避免出现 `0/6 但 100%`、全部作品失败却显示完成等假状态。

## 8. 继续、重试、接力与中止

### 8.1 真正的“继续”

继续不是从第一个词重跑。系统应：

1. 读取最近有效检查点；
2. 跳过已经终态成功或业务性跳过的工作项；
3. 从最后未完成项继续；
4. 创建新的尝试记录，旧尝试保留用于审计；
5. 使用尝试编号和进度序号阻止旧心跳覆盖。

这属于“业务状态续跑”，不是把一个浏览器的实时页面迁移到另一台设备。

### 8.2 仅重试失败项

适用于临时网络、页面未完成加载或可重试的服务异常。默认失败工作项最多自动尝试 `2` 次，超过后进入失败或人工处理。

### 8.3 换 Agent 接力

适用于原 Agent 离线、长期无进展或账号需要休息。只转移剩余工作项；已完成结果继续归属于父任务。

验证码、安全验证、明确风控码等账号风险不能静默自动接力，必须提示人工确认，避免多账号连续触发平台风控。

### 8.4 中止

- 未领取任务可在服务端直接取消；
- 已领取任务下发 `stop` 命令；
- Agent 离线时显示“上线后停止”；
- 重复中止应幂等；
- 已采数据和审计事件保留。

## 9. 平台异常的业务语义

| 场景 | 结果 | 是否重试 | 是否需要人工 |
| --- | --- | --- | --- |
| 抖音“服务出现异常” | 当前关键词搜索服务异常 | 可跳过该词并继续后续词 | 否 |
| 抖音验证码/安全验证 | 账号或访问风险 | 停止当前 Agent | 是 |
| 抖音作品不存在/已删除 | 业务结果：内容不可用 | 否 | 否 |
| 小红书“当前笔记暂时无法浏览” | 业务结果：删除或不可用 | 否 | 否 |
| 小红书明确安全拦截 | 账号风险 | 暂停 | 是 |
| 搜索无结果/筛选后无结果 | 业务结果：范围内未发现 | 否 | 否 |
| 详情未就绪 | 先区分页面仍加载、跳转、ID 不匹配 | 有条件 | 视原因 |
| 目标作品 ID 不匹配 | 禁止云端写回 | 重新定位目标 | 持续发生时需要 |

删除、无结果、发布日期不在范围内都不应算“未完成”；它们是可解释的业务终态。

## 10. 安全与租户隔离

- Agent 令牌不能登录管理后台，只能上报自身心跳、任务和命令回执。
- 令牌绑定租户、激活码和环境绑定；激活码过期、冻结、删除或解绑后立即失效。
- 后台读写由登录会话和租户角色控制。
- 任务、工作项、事件、命令和快照均由服务端租户上下文过滤，不接受前端自行指定租户。
- 任务正文进入本地账本和日志前必须清除激活码、令牌、Cookie 等凭证。
- 所有远程创建、停止、恢复和重分配操作应留下审计事件。
- 租户数据复制仅复制业务数据和配置，不能复制用户会话、Agent 令牌、激活码绑定或平台登录态。

## 11. 数据模型与迁移

核心表族：

- `capture_agents`：Agent 身份、能力、归组、状态和计划镜像；
- `capture_agent_tokens`：Agent 令牌哈希；
- `capture_tasks`：云端任务当前态；
- `capture_task_attempts`：每次执行尝试；
- `capture_task_items`：关键词、帖子等最小工作项；
- `capture_task_events`：追加式审计事件；
- `capture_task_snapshots`：追加式状态快照；
- `capture_agent_commands`：创建、继续、停止等持久化命令；
- 多 Agent 编排、定时计划、提醒与可用性字段由后续迁移扩展。

任务中心从 `032_cloud_capture_task_center.sql` 建立基础模型，当前稳定基线相关迁移已延伸至 `050_ticket_comment_record_link.sql`。数据库说明见 [数据库与迁移说明](./数据库与迁移说明.md)。

## 12. 运营验收

### 单 Agent

1. 创建一次性任务，确认后台和 Extension 同时出现同一任务。
2. 停止任务，确认本地与云端一致进入中止，已采结果仍存在。
3. 中断后点击继续，确认从检查点继续而非从第一个词重跑。
4. 关闭浏览器，两分钟后确认离线；离线分配任务后上线可领取。

### 多 Agent

1. 用 20 个关键词、4 个 Agent 创建任务，确认每个 5 个且无重复。
2. 让其中一个 Agent 离线，确认已完成项不动、剩余项可重分配。
3. 让一个 Agent 遇到安全验证，确认任务进入人工处理且不自动跨账号试探。
4. 所有工作项结束后，核对父任务的成功、跳过、失败和人工处理数量。

### 无人值守

1. 保存计划时不立即运行。
2. 到达时间后只创建一次真实任务。
3. 指定日期结束后显示无后续排期。
4. 重叠触发被跳过，运行记录仍可审计。

### 状态一致性

1. 设备心跳、任务心跳、业务进展三种时间分别可见。
2. 重放旧快照不能覆盖新尝试。
3. Extension 完成后后台不残留执行中，后台中止后 Extension 不继续运行。
4. 删除/无结果/范围外内容按业务结果结算，不进入无休止重试。

更完整的发布门禁和故障定位见 [故障排查与验收清单](./故障排查与验收清单.md)。
