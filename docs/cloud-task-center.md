# 云端采集任务中心

## 目标

云端任务中心解决三个运营问题：

1. 客户后台可以看到各采集环境是否在线、正在执行什么任务，以及设备心跳和真实业务进展。
2. 无人值守关键词任务中断后，客户即使不在采集电脑旁，也可以从后台发出“继续剩余任务”指令。
3. 客户后台可以选择一个明确的浏览器节点创建“一次性采集”或保存“无人值守计划”；在线节点领取后处理，离线节点保留指令等待上线。
4. 远程任务会出现在扩展右侧的统一运行界面，用户可在扩展本机停止，也可从后台远程停止并保留已采结果。

它不是把小红书或抖音采集本身搬到云服务器。采集仍由客户浏览器执行，云端保存任务镜像、节点状态、恢复指令和审计事件。

## 设备与浏览器模型

- 一个浏览器配置目录（profile）对应一个采集节点 `capture_agent`。
- 一台物理电脑可以包含多个采集节点，通过相同的“所属设备”名称归组。
- Chrome 和 Edge，或两个相互独立的 Chrome profile，会有各自的扩展存储、登录态、环境绑定和采集锁，因此可以分别运行小红书与抖音。
- 同一浏览器 profile 中打开两个普通窗口仍共享同一采集锁，不应当当作两个节点使用。
- 浏览器无法可靠读取隐私安全的物理机器 ID，所以首次注册默认不自动合并设备。管理员需要在后台把两个节点的“所属设备”改成同一个名称，例如“办公室电脑 01”。
- “允许执行的平台”用于明确节点分工，后台远程继续时会校验任务平台是否属于该节点；第一版不会阻止用户在本地手工发起其他平台任务。

两个浏览器节点会分别占用一个激活码环境绑定名额。部署前应确认激活码的 `max_bindings` 足够。

## 工作链路

1. 扩展验证激活码后，服务端签发只属于该浏览器节点的随机令牌。数据库只保存令牌哈希。
2. 扩展每分钟发送一次心跳，并在任务账本变化后尽快上报；连续两分钟没有设备心跳即显示离线。
3. 心跳同时镜像该节点当前保存的无人值守计划。计划镜像与任务分开保存，不会在任务列表中产生无业务意义的“同步任务”。
4. 心跳上报最多 50 个最近任务，云端按“租户 + 节点 + 本地任务 ID”幂等合并。
5. 后台分别显示三类时间：设备心跳代表浏览器节点在线，任务心跳代表执行循环仍在运行，业务进展代表采集数量或检查点真正推进。设备心跳新但任务心跳旧，表示任务没有运行；任务心跳新但业务进展旧，表示循环还活着但采集可能卡住；三者都旧通常表示浏览器已离线。
6. 后台新建任务时生成一个稳定 ID，同时作为云端占位任务 ID 和设备处理该指令的幂等 ID。后续心跳更新同一行，不会生成重复任务卡片。
7. `executionMode=one_time` 时，在线节点收到 `create` 指令后立即创建一次性本地任务；设备回执后进入“已认领”，真实任务心跳开始后显示“运行中”。这个模式不会覆盖设备原有的无人值守计划。
8. `executionMode=unattended_plan` 时，设备保存并启用计划，但不会因为“保存计划”立即运行；计划到点后再产生真实采集任务。计划配置记录用于审计，单条数据同步不会拆成业务任务卡片。
9. 对已中断、失败或需要处理的任务，后台可以创建恢复指令；扩展按本地检查点创建新的恢复任务，旧任务标记为“已转入恢复任务”。
10. 对待领取、执行中或仍可恢复的远程任务，后台可以停止。尚未下发的创建指令会直接取消；设备已领取时下发 `stop`，停止指令优先于创建和继续指令。
11. 指令结果会在本地缓存。即使执行成功后回执遇到网络中断，后续心跳也只会补发回执，不会重复创建、恢复、配置或停止任务。

## 数据模型

- `capture_agents`：浏览器节点、所属物理设备、平台分工、授权关系、心跳和当前本地无人值守计划镜像。
- `capture_agent_tokens`：节点令牌哈希；每个节点保留一个很小的并发验证窗口，避免响应乱序让浏览器保存失效令牌。
- `capture_tasks`：本地任务的云端镜像、状态、进度、检查点和统计数据。
- `capture_task_attempts`：每次执行尝试的心跳、业务进展和结果。
- `capture_task_snapshots`：只追加、不覆盖的已接收快照历史；当前态仍由 `capture_tasks` / `capture_task_attempts` 提供。
- `capture_task_items`：为后续逐作品精确补采预留的任务项模型。
- `capture_task_events`：节点上报、状态变化、人工继续和指令结果的审计轨迹。
- `capture_agent_commands`：发给指定节点的持久化 `create`、`resume`、`stop` 指令。`create` 的 `executionMode` 区分一次性采集与无人值守计划配置。

迁移文件：

- `server/db/migrations/032_cloud_capture_task_center.sql`：云任务中心基础表。
- `server/db/migrations/033_cloud_remote_task_creation.sql`：节点计划镜像与 `create` 指令。033 保持独立，避免已应用 032 的数据库因修改旧迁移而产生结构漂移。
- `server/db/migrations/034_capture_task_snapshot_history.sql`：追加式任务快照历史、幂等指纹和倒序查询索引。

## 权限与安全

- 节点令牌不能登录管理后台，只能上报心跳、镜像任务和提交自身指令回执。
- 节点令牌同时绑定租户、激活码和环境绑定；激活码过期、冻结、删除，或环境绑定被移除后，节点请求立即失效。
- 后台总览只允许登录会话读取；节点配置、远程创建、继续和停止都要求租户写权限。
- 所有任务、节点、事件和命令查询都按服务端解析出的 `tenant_id` 隔离，不接受客户端自行指定租户。
- `POST /api/capture-cloud/agents/:id/tasks` 只允许后台登录会话和租户写角色；目标节点、授权码、环境绑定、平台分工均按同一服务端租户校验。
- 云端新建任务要求节点明确上报 `remoteTaskCreate` 能力；远程保存计划还要求 `remoteUnattendedPlanWrite`，远程停止要求 `remoteStop`。旧扩展不会显示或收到不支持的控制动作。
- 本地任务账本会先做凭证字段脱敏；心跳正文不包含激活码或节点令牌，令牌只出现在 `Authorization` 请求头中。
- 新建任务只接受白名单归一化后的计划字段（平台、1–30 个关键词、搜索筛选、轮次和间隔），不会把任意后台 JSON 直接交给浏览器执行。

## 第一版边界

- 只能继续扩展当前明确声明了 `control_task_id` 的可控制无人值守关键词请求；历史任务即使保留检查点，以及普通手工单篇/列表任务，目前都只能查看，不能从后台接管。
- 云端不能唤醒关机的电脑，也不能绕过浏览器休眠策略。离线时只保存指令，等待设备和浏览器重新上线。
- 云端新建任务必须明确选择一个节点，不会在多个节点之间自动抢占、迁移或调度。第一版不支持微博云端新建任务。
- 一个浏览器节点同一时间只执行一个当前采集请求。节点有可恢复旧任务时，新建的一次性任务仍会持久化为 `pending` 队列项；无人值守计划配置可以先保存，到点运行时再服从同一执行锁。
- 远程任务从 `pending/claimed` 阶段起就会显示在扩展运行界面，不依赖浏览器 Debug 会话已经建立；本机“停止”和后台“停止”都精确指向同一个任务 ID。
- 任务中心不共享小红书/抖音 Cookie。每个浏览器节点继续使用自己的平台登录态。

## 新建任务接口

`POST /api/capture-cloud/agents/:id/tasks` 接受：

```json
{
  "clientTaskId": "b44c62a2-1ef8-40da-89ea-55b1d5b9a29d",
  "executionMode": "one_time",
  "platform": "xiaohongshu",
  "keywords": ["新能源", "智能座舱"],
  "sort": "latest",
  "publishTime": "week",
  "maxRounds": 1,
  "roundGapMin": 10
}
```

保存无人值守计划时使用同一接口，并传入完整计划字段：

```json
{
  "requestKey": "9c458a7c-b082-4fac-bc75-d981f35ab20e",
  "executionMode": "unattended_plan",
  "platform": "douyin",
  "keywords": ["新能源", "智能座舱"],
  "mode": "daily",
  "startTime": "09:00",
  "randomOffsetMin": 20,
  "customDates": "",
  "sort": "latest",
  "publishTime": "week",
  "maxRounds": 2,
  "roundGapMin": 10
}
```

不传 `executionMode` 时保持兼容，默认按 `one_time` 执行。`unattended_plan` 只保存计划；`mode=custom_dates` 时 `customDates` 使用 `YYYY-MM-DD` 日期清单。

`clientTaskId`（也可用同义字段 `requestKey`）是必填项，由调用方为一次提交生成并在超时重试时复用的小写 UUID；服务端把它同时用作云端占位任务和浏览器本地请求的稳定 ID。相同节点、相同 ID 和相同规范化参数会幂等返回原任务（包括已经完成或失败的状态），同 ID 不同参数返回 `409 idempotency_key_conflict`；缺失时返回 `400 request_key_required`，避免网络超时重试制造重复任务。

服务端在一个事务内创建 `capture_tasks` 占位行、`create` 指令和审计事件。响应中的状态为在线节点的 `pending` 或离线节点的 `waiting_device`；数据库源状态仍为 `pending`，离线展示状态由设备心跳派生。设备心跳收到指令时只确认命令，不会把可能仍在排队的任务误标为已认领；设备成功创建本地任务的回执才推进到 `claimed`，真实任务心跳再推进到 `running`。创建失败进入 `needs_action`，未领取且超过有效期进入 `failed`；与指令 ID 精确匹配的迟到回执或任务心跳可以纠正过期边界产生的假失败。

## 停止任务接口

`POST /api/capture-cloud/tasks/:id/stop` 不需要额外正文。重复点击会复用同一条有效停止指令；任务已取消时幂等返回成功。设备离线时停止指令在云端排队，后台显示“上线后停止”。尚未被设备领取的一次性任务会在服务端直接取消，不再发送无意义的停止指令。

## 快照历史接口

`GET /api/capture-cloud/tasks/:id/snapshots?limit=100` 返回指定任务已通过新鲜度校验的追加式快照历史，按来源更新时间倒序排列；默认 100 条，最多 500 条。重复上报使用快照指纹幂等去重，旧进度、旧尝试以及同一尝试编号下不匹配的执行 ID 不会覆盖当前态，也不会进入有效历史。

## 发布与验收

1. 部署服务端，让启动流程依次应用迁移 `032_cloud_capture_task_center.sql`、`033_cloud_remote_task_creation.sql` 和 `034_capture_task_snapshot_history.sql`。
2. 构建并发布 `web/admin`，确认“采集任务”默认进入云端任务中心。
3. 本机验收运行 `scripts/sync-extension-build.zsh local` 并在两个浏览器中 Reload；客户交付包只允许通过 `scripts/package-extension.zsh` 生成，脚本会强制校验生产 API 地址。
4. 两个浏览器分别重新验证激活码，使其取得节点令牌并出现在后台。
5. 在后台把两个节点的“所属设备”改成同一个名称，并分别勾选小红书、抖音。
6. 在两个浏览器分别启动任务，确认后台显示两条独立节点心跳和两组独立进度。
7. 人为中断一条无人值守任务，在后台点击“继续剩余任务”，确认在线节点领取指令、旧任务显示“已转入恢复任务”、新恢复任务开始上报。
8. 关闭一个浏览器后确认两分钟内变为离线；离线点击继续时应显示“上线后继续”，浏览器重开后领取该指令。
9. 在在线节点上创建“一次性采集”，确认扩展右侧立即出现统一运行页；分别从扩展和后台停止一次，确认任务进入“已取消”且已有结果保留。
10. 从后台保存“无人值守计划”，确认设备节点的计划镜像更新、没有立即启动采集；到达计划时间后才出现真实任务。
11. 关闭另一个浏览器后创建一次性任务，确认显示“等待设备”；浏览器重开后领取并执行，且指令过期前不会被其他节点领取。再验证离线点击停止显示“上线后停止”，浏览器上线后自动取消。
12. 运行中的同一任务至少推进两次进度，确认 `capture_task_snapshots` 保留多条快照；重放相同快照不重复，旧尝试不能覆盖新尝试。
