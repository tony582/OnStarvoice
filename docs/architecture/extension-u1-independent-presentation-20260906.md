## 交付的代码边界

```text
已授权且按范围读取的记录快照（未来数据源接入）
  ├─ adaptStoredSummary → 规范摘要 → presentResult / presentResultPage
  └─ 按精确 ID 请求详情 → adaptStoredDetail → presentResultDetail

两条路径都无存储、网络、DOM、采集、同步、重试副作用。
```

这不是新的任务状态机：展示层不判定重跑许可、不释放待核对状态、不替代业务鉴权，也不根据显示成功触发业务操作。

| 文件 | 职责 |
| --- | --- |
| `extension-ui/domain/record-id.mjs` | 精确记录 ID 校验，不截断、不 trim、不替换字符 |
| `extension-ui/domain/result-presenter.mjs` | 独立结果/详情展示模型；分别表达采集与保存确认 |
| `extension-ui/domain/result-page.mjs` | 摘要分页和需处理筛选，最多返回 50 条，不读取大字段 |
| `extension-ui/adapters/stored-result.mjs` | 旧快照形状转换，不导入旧渲染或旧数据池读取器 |
| `scripts/check-extension-ui-boundary.mjs` | 检查真实新源码及测试 fixture 的静态依赖/副作用边界 |

默认文案不冻结 UIUX 的最终用语。设计任务可以重新定义措辞，接入时以语义状态键映射，不能改变“未核对”与“失败”等状态的事实含义。

## 映射证据与刻意保留的不确定性

本次只读核对 main 源码和原工作区 `extension-build/`，没有读取客户数据或操作平台页面。客户包参考路径为 `/Users/dulaidila/.gemini/antigravity/scratch/OnStarvoice-2/extension-build`。

1. `utils/platform/record-envelope.js` 的序列化结果存 `normalizedPayload/rawPayload`，磁盘对象不带内存 `payload` 别名。适配器按 `normalizedPayload → payload → data` 选择首个存在的层；已存在但损坏时不回退复活旧值，完全不读 rawPayload。
2. `utils/storage.js` 的 `getDataPool` 会归一化并可能修复重复 ID 写回，因此本批不把它当作无副作用数据源。
3. `capture-sync` 的存储构造将搜索/博主列表拆成一条一个 `items:[item]`；新摘要只读该条的轻量字段，不读详情、正文或整份评论。
4. 抖音视频在记录层仍可为 `single_note`，新内容种类不根据平台瞎猜。作者主页的获赞/收藏汇总不冒充作品点赞。显式平台标签支持小红书、抖音、微博；微博原本的 single_note/博主记录使用同一信封，不因新展示内核遗漏平台而降成未知。这只是记录转换，不是新增微博采集能力。
5. `record.status` 只有 draft/synced/failed 的历史同步含义，失败写入也会更新时间。旧成功状态、时间戳、聚合数量或任意调用方 `delivery` 声明，都不证明本次服务器/本地双确认。
6. note/profile 的完整采集证据不足则为 unknown；独立 comments 记录的 `captureStatus` 仅映射该条评论记录，并附 `captureScope: comment_record`。
7. 作品的 comments 是平台显示数量；独立 comments 记录的 totalCount 是该记录的采集数量。两者不能用最多 50 条的评论预览长度替代。
8. 正数指标允许缺省 known 标志；零必须有明确 known 证据。任何明确 false、格式错误、冲突或不可读 known 证据都降为未知。
9. E1h 中尚未交付的待核对信号只作为可识别的警示兼容输入；不能据此声称客户已有该协议。这里永远不返回操作许可。
