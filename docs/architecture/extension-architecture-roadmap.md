## 1. 目标与纠偏

目标是让后台执行、采集提交、Sidebar 控制和平台采集分别拥有完整职责，降低大文件改动的连带风险。
保留现有稳定行为；不是借重构重写采集规则、增加重试、降低平台等待或改变客户数据格式。
此前 E 系列抽出少量真实调用的 helper，并补充保存可靠性与协议原型；尚未完成主干状态机和流水线拆分。
U1–U5 建立独立读取、展示与权限边界，尚未替换旧运行链路，不能计入 E1 核心拆分完成量。
从本轮开始暂停 U 系列新增小功能；只在主干接线确实需要时复用或补齐它，不再成为默认下一批。

原 P7 顺序为协议/DTO → 状态机 → 平台 → 同步 → Sidebar。
R0 已将执行上下文和后台状态提前，再做提交链、Sidebar、新平台模块；本文沿用这一调整并固定为 L1–L6。
文档独立复核发现剩余后台职责缺少最终归宿，因此补列 L5 后台宿主收尾，原组合验收顺延为 L6；这是计划补全，不是又一条并行 helper 功能线。
先冻结协议，再改内部职责；平台选择器与行为不随拆分一起改变。G3 未关闭的事实不因 Extension 提前而改变。

### L1 已完成候选合同（历史保留）

L1 的当前核心目标是后台持久采集辅助生命周期，不承诺本批迁走整个业务状态机。以下是内部步骤，不是四个可分别宣布“完整架构完成”的批次。

1. **盘点与固定行为**：列出所有开始、更新、注册工作页、停止、结束、恢复入口；记录身份、状态读写和副作用次序。
2. **迁移状态与职责**：模块拥有执行 session 的内存状态、owner/worker 关系和串行生命周期操作；外部依赖通过明确适配器注入。
3. **真实入口接线与旧代码退出**：原消息/事件入口调用新模块；保留同名 facade 兼容调用方，移除原位置的重复实现与隐式写状态旁路。
4. **行为对照与收口**：按原入口运行基点/候选配对测试；证明状态、资源归属、持久化顺序及迟到事件处置等价。

每个被迁移职责必须登记以下四项，未填完整就不算迁移完成：

| 登记项 | 必须回答的问题 |
| --- | --- |
| 状态所有权 | 谁持有/更新 session、owner、worker、锁引用？持久状态仍由哪条兼容存储路径保存？ |
| 调用清单 | 原消息监听、Sidebar、云任务、无人值守、监控及恢复入口，哪些调用新模块，哪些确实不涉及？ |
| 副作用顺序 | 锁/worker 登记、页面导航、状态持久化、取消、debugger/页面/组释放，原顺序在哪里被验证？ |
| 退出清单 | 哪些旧函数体/全局写入已删除？哪些 facade 暂留、由谁调用、何时可以删除？ |

不把四种上下文混成一个全局 current task：诊断上下文、本地 session、Sidebar owner、云 task/Attempt 各保留身份边界。
begin/update/end、owner 端口、task/Attempt/requestId、存储键与状态名称保持兼容；现有旧字段兼容只能原样保留，不自行扩大。
停止阻止新采集和业务轮次；保留已本地确认记录，按现有身份与幂等规则结算在途结果；迟到事件不能复活停止或覆盖新 Attempt。
关闭失败保留可重试回收的资源归属；不能为了让 UI 显示完成而先清掉 owner/锁证据。
owner 断连宽限、锁租约、恢复预算、防风控等待、并发和重试次数均不在 L1 中调优。

## 6. 验证与完成定义

每个阶段交付必须同时具备：职责迁移表、旧/新调用图或调用清单、状态所有权表、兼容清单、旧代码退出清单和可复现行为证据。

阶段状态只允许：待实施 → 实施中 → 候选接线完成/待审阅 → 阶段技术验收完成；发布状态单独记录。
L1–L3 完整职责的候选接线、独立审阅及隔离验证通过、接口稳定后，可继续下一阶段的隔离开发；真实浏览器/长期缺口仍须逐项保留，不能记为完整技术验收或 G7 关闭。

停线条件：基点/稳定 hotfix 变化未核对；协议/存储兼容破坏；串租户/任务；旧事件覆盖新 Attempt；重复提交、数据丢失、停止后复活；资源归属丢失；回归或 CI 失败。
出现上述情况先停止该候选推进、保留复现证据并修正计划；不操作客户任务/存储来“补偿”测试差异。

回滚以精确上一兼容提交和隔离快照为单位；保留 facade 便于审阅回退，禁止运行新旧两套执行器做双重采集/提交。
本阶段不改持久化格式；若候选状态无法被旧稳定包读取，停止进入发布准备，先设计兼容与恢复验证。
未来客户灰度前保存旧包、哈希、版本与 Profile 范围，明确人工安装/Reload步骤；服务器回退不等于浏览器插件回退。
回退不清空用户数据、不自动删除未同步记录；当前未发布候选的回退不需要触碰客户环境。
