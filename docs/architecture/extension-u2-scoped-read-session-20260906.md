## 解决的下一层边界

U1 已能把单条历史记录转成独立展示模型，但调用方仍负责安全读取、分页和选择详情。U2 把以下规则变成可执行代码：

1. 一个会话只绑定一个明确的 tenant/task/execution 范围，不存在缺失范围后读全部记录的回退。
2. 摘要页由注入的数据源分页，单次最多接收 50 条；不调用 U1 的全数组分页器再次扫描整个池。
3. 详情只读取当前已接收页面内的精确 ID，并绑定该页面快照。当前页重复 ID 可以展示，但不能猜测应该打开哪条。
4. 刷新页面立即取消旧页面和详情的本地等待；新详情请求使旧详情失效。关闭不等待数据源。
5. 请求已完成但其 Promise 结果尚未被视图消费时，仍提供 `isCurrent(requestToken)` 校验。未来视图在应用任何成功或错误状态前都必须检查，不能只靠取消在途请求。

```text
未来可信数据源（真实权限校验 + 范围隔离 + 摘要分页/单条详情）
  → read-contract：范围/查询/快照/ID/分页一致性校验
  → result-read-session：请求替换、取消、超时、关闭、当前结果校验
  → U1 独立展示模型
  → 未来选定 UI（尚未实现）
```

这不是鉴权实现。数据源回传相同 scope 只能发现错配，不能证明用户有权限，更不能证明该记录确实属于这个范围。

## 接口约定

`createResultReadSession({ scope, source, timeoutMs? })` 返回冻结的本地会话接口。

- scope 是三个必须存在的精确字符串：`tenantId / taskId / executionId`。本批拟议契约每项最多 240 字符，禁止空白、控制字符、双向控制字符和孤立代理项；不拼接后比较、不 trim、不转换数字。这不是对现有服务端字段的自动映射。
- 记录 ID 沿用 U1 的精确 128 字符契约。源快照 `snapshotId` 使用新的 240 字符不透明标识约定，不从时间戳或历史同步状态推导。
- 协调器只读取并调用 source 的两个 own-data 方法，不向结果传播其余属性。调用保留源方法的 this，source 是可信能力而不是沙箱，必须真正只读。不导入原数据池读取器，因为该读取器可能归一化并写回。
- timeoutMs 缺省 3000，可设置 1–30000 的整数。超时只结束本地读取等待并发送协作取消信号，不能中断同步阻塞代码，也不证明底层工作已回收。

| 调用 | 数据源输入 | 数据源返回 |
| --- | --- | --- |
| `readPage({ filter?, offset?, limit? })` | `readSummaryPage({ scope, query, signal })` | `{ scope, snapshotId, query, items, counts }` |
| `readDetail({ recordId, pageToken })` | `readRecordDetail({ scope, snapshotId, recordId, signal })` | `{ scope, snapshotId, recordId, detail }` |

query 缺省 `all / 0 / 50`。filter 只允许 `all / attention`；offset 为非负安全整数；limit 为 1–50 的整数。未知 filter 和非法分页值拒绝；未使用的额外字段忽略且不转发。源响应必须明确回传全部查询字段。

items 是已经按 query 筛选并分页的 U1 规范摘要，不是完整记录池。counts 为同一范围/同一快照的 `all / attention / matching`，matching 必须与筛选对应。attention 须遵循 U1 `presentResult(...).needsAttention` 的语义，不能用旧 synced/failed 计数替代。条数必须等于 `min(limit, max(0, matching - offset))`；计数还要与本页状态相容。这里只检验可见页的一致性，不验证整个数据集统计。

detail 是 U1 规范详情。历史源的未来适配器应先通过已授权精确读取取得单条记录，再用 `adaptStoredDetail`，不能把 rawPayload 或原始业务信封透传给展示层。

### 结果与生命周期

- 每个读取结果有稳定 `status` 和不透明的本地 `requestToken`。
- page 成功返回 `{ status: 'ready', requestToken, pageToken, page }`；空数据是经过完整校验的成功空页，不是异常的替代品。
- detail 成功返回 `{ status: 'ready', requestToken, recordId, detail }`。
- 其余状态：`invalid_request / selection_unavailable / invalid_response / read_failed / timed_out / superseded / cancelled / closed`。不返回源异常消息、原始输入或失败时的部分内容，不自动重试。
- pageToken 是当前成功页的本地对象身份。不能用相同属性的新对象、其他会话的 token 或上一页 token 查询详情；也不能跨刷新、进程或执行复用。它不是服务端授权凭证。
- 每次 `readPage` 都先清掉上一页的选择资格，包含非法查询或失败的新查询。每次 `readDetail` 都先失效上一详情请求，包含非法详情请求。
- `cancel()` 清掉当前选择和请求，但允许之后重新读页。`close()` 永久关闭会话；换任务必须先关闭，再创建新会话。两者均不等待源 Promise 结束。
- `isCurrent(result.requestToken)` 必须紧贴视图更新前调用，且其后到更新间不能再异步等待；已结束请求的结果无法被撤销，不能不经检查直接显示。
- 内部不保存完整页/详情/跨执行缓存，只保留当前页快照和至多 50 个 ID 的出现次数。源忽略取消时仍可能持有自己的 Promise 和资源，本批不声称解决底层内存增长。

## 未来实际数据源必须履行的责任

1. 以可信身份完成鉴权，且每次读取核验账户/会话是否仍有效；页面传来的 tenant/task/execution 不构成权限。
2. 在数据源完成范围隔离、稳定排序、筛选和分页；摘要不载入正文/评论，详情按精确范围 + ID 查询。全量读取后切片不算存储优化。
3. 为一致的摘要与详情提供真实快照/修订绑定，读取期间发生变化应明确拒绝或使用一致快照，不能把旧内容标成新快照。
4. 在整个范围/快照中校验 ID 唯一性，避免跨页重复 ID 被误认为单条。U2 只拒绝当前页可见的重复，不能证明源全局唯一。
5. 历史同步状态仍不能当成当前远端/本地双确认。经过 U1 历史适配器的记录仍为未核对，不据此自动重试。
6. 只读适配器不触发 ID 修复、自动同步、保存、迁移或任务状态变更；支持取消并释放资源。需要写操作的命令层另行设计验收。

实际存储仍是原来的结构。本批不是 IndexedDB 迁移，没有改善已运行客户版的数据库读写，不能把 fixture 单测当作浏览器性能或 8 小时稳定性验收。

## 验证与接续

本批使用人工数据和注入源做契约、故障及竞态验证，不读取客户数据。验收覆盖范围/快照/精确 ID 错配、重复 ID、页数/计数不一致、已结束但迟消费结果、永不完成源、取消/关闭/超时、不重试、错误脱敏、getter 不执行和输入不变性。真实源目录继续通过 U1 的静态依赖门禁，该门禁不是任意 JavaScript 的安全沙箱。
