## 本轮范围与状态边界

初审核心 138 函数约 11,077 行；状态写入复核发现恢复、监控和进度投影仍写同一控制状态，因此在动源码前补入这些完整职责，确定 **165 个原函数、约 13,078 行原函数体**，不是承诺净减行数。
按职责划分 task ledger/assist、owner、unattended control、progress projection、manual capture、cancel/streaming、keyword batch、unattended reporting/closure、execution lock、targeted、unattended run、capture action/cancel、monitor execution、detail/sync、record retry、recovery、progress、URL batch。

- 62 项任务控制绑定迁入 controller 实例，含原 Set/Map、owner、Attempt、取消、worker、节流、心跳和最终回报队列；不复制锁或新建任务账本。
- 未迁出宿主只读的 8 项状态经具名读取方法访问，不暴露整个 state 或可写 state bag。读取兼容值可能仍含旧对象引用，不能宣称深不可变或安全隔离。
- `keywordSortDimension`、`expandedKeywordsBuffer`、`keywordPlanState`、`activeKeywordRunState` 暂由宿主拥有；按名称提供实时 getter，后两项显式 setter 保持旧赋值顺序，列入 B 的收口清单。固定常量/集合通过原引用注入。
- 保留原 L1/L2、storage、record-sync-queue 端口和等待/重试/并发/平台采集规则。恢复 UI 先与其唯一状态 owner 同迁；DOM、文案和表单仍是兼容依赖，本批不伪称视图完全解耦。
- 原 5 处被迁移函数内的动态 storage import 改为明确 `loadStorageModule` 宿主端口，保留同一模块解析目标与惰性调用时机；不因目录移动改错路径或提前读取数据。
- Sidebar 原自动初始化可能在非 loading 状态立即运行；实例装配必须位于全部声明初始化之后、自动初始化之前。保留 loading/ready 两条启动路径和 beforeunload/pagehide 的注册次序；关闭 owner 的原三步移入具名操作，不让宿主继续写私有状态。

## UI 设计与 U5 已核对，哪些还未接线

本轮已读取“重新设计 Extension UIUX”和“评估Extension反编译防护”的实际任务内容，不只凭任务标题。设计交付为方向 A 完整交互参考及 Figma 第 7 页（node `21-2`），强调标准单选/多选、条件与半选、校验/禁用/加载、三平台、独立任务场景与双轨结果；它没有修改 Extension 运行代码。
U5 精确独立候选为 `60ea0243eb6be2a794a88a3aa95d910169752d0b`，不是本轮父分支，不能整分支覆盖稳定候选。

1. U4 已实现“业务授权到期但身份/租户/成员/设备/范围证据仍有效时允许历史只读”的独立策略；无效、撤权、冻结不放行，新采集不放行。不能继续写成政策未定义；真实身份供给与执行端拦截仍未接。
2. U5 已贯通 `unverified / hasIssue / interventionReported` 读取与筛选；三者可重叠，历史介入报告不代表当前有待办，旧 `synced` 不是当前双确认。不能把这些读模型状态转为停止/重试/删除/导出权限。
3. 旧 `handleTaskCenterAction` 使用 taskId/requestId 兼容映射及停止回退，不能直接接成新视图的安全命令协议；B 必须单独核对精确目标与现时权限。
4. U5 的读取 cancel 不等于业务停止，结果状态不能替代 `stopping` 的命令生命周期；停止请求、收尾和停止确认分别来自运行证据，不借拆分提前承诺停止成功。
5. 旧诊断 taskId/correlationId 及公开 auth 展示缺少 U5 所需可信归属/identity/evidenceRevision；不能给历史记录补造 tenant/task/execution，也不能从当前登录推定所有记录可读。
6. 微博搜索及部分转发/分享/收藏指标已有旧能力，不能按原型想象删掉或另造；U5 的平台筛选、更多指标和任务级交付统计仍需接口。设计中的示例回执、900ms 切页和硬编码平台不进入真实运行。

本轮不增加 U 小功能，不假接数据供给，不启用 E1e/E1i producer，不修复或掩盖 L2 记录的远端成功/本地确认失败风险。来源/工作流/词语/资产和权属处置继续按总计划独立验收；拆文件不作为独立性法律结论。

## 实际结果

### 真实源码与剩余边界

- `sidebar/sidebar-logic.js` 从 **31,430 → 18,530 行，净减 12,900 行**。165 个原函数迁入 18 个职责模块加 coordinator，512 个原宿主函数保留；唯一原 `initSidebar` 导出不变，没有复制第二套控制器。
- 62 项控制状态由实例唯一拥有；宿主通过 8 个具名查询读取，4 项共享计划/输入绑定仍显式由宿主拥有。217 个宿主能力端口保留原引用和调用语义；165 项操作、8 项查询和 shutdown 合计 174 项兼容入口，不宣称已收窄成最终最小接口。
- 模块仍含 DOM、表单、文案兼容逻辑，部分任务函数仍较长；两项对象查询保留旧引用，并非深不可变 DTO。L3-B 必须继续拆开任务域与视图，清理共享计划绑定及旧动作路由；L3-C 才接 U5 和新设计，不能只靠文件变小宣布完成。
- 等待、重试、并发、执行锁、持久化格式及采集规则不变。装配位于全部声明之后、首次初始化之前；没有新增启动、取消、网络或采集副作用。
