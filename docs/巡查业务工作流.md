# StarVoice 星语 · 巡查业务工作流

> 适用范围：当前稳定版后台、Extension 与云端调度中心。
>
> 目标读者：产品、实施、客户成功、运营、测试和研发。
>
> 文档定位：说明各类巡查“管理什么、在哪里创建、由谁执行、结果到哪里、什么不属于它”。
>
> 核对日期：2026-07-30。版本号以实际安装包和页面显示为准。
>
> 事实来源：当前代码、数据库迁移和生产配置优先于本文；平台页面或接口调整后，应同步更新本文。

---

## 1. 先理解六类核心对象

StarVoice 的巡查不是一个页面完成全部工作，而是六类对象共同组成的业务链路。

| 对象 | 含义 | 典型入口 | 关键边界 |
|---|---|---|---|
| 关注博主 | 需要持续观察的普通创作者、竞品账号或行业账号 | 关注博主 | 管理关注关系和动态，不等同于官方账号 |
| 官方账号 | 客户自己或客户指定的官方账号 | 关注博主 → 官方账号评论巡查；平台管理 → 官方账号 | 必须依靠明确身份登记，不能仅靠名称包含关系判断 |
| 负面帖子 | 已发现且需要继续观察变化的负面内容 | 内容分诊 → 舆情巡查；调度中心 → 负面帖子巡查 | 追踪已知内容，不负责无目标地全网发现 |
| Agent | 一个已激活并保持心跳的浏览器 Extension 节点 | 调度中心右侧执行节点 | 一个浏览器实例就是一个 Agent，不等同于一台电脑 |
| 业务任务 | 用户要完成的一次业务目标 | 调度中心 | 可拆成多个工作项分配给一个或多个 Agent |
| 工单 | 已经明确需要人工跟进的处置事项 | 内容分诊 → 已转工单、记录进展、结案归档 | 必须由用户明确转入；转单后进入“已转工单”处理模式，结案时自动归档 |

还要区分三个容易混淆的数据层次：

1. **业务记录**：一篇作品、一条评论、一个博主或一个官方账号。
2. **任务执行记录**：某个 Agent 在某个时间执行了什么、成功或失败在哪里。
3. **快照**：同一篇内容在不同时间的点赞、评论、收藏、转发和可用状态。

业务记录用于运营处置，任务记录用于诊断，快照用于趋势和舆情变化分析。三者不能相互替代。

## 2. 总体业务链路

```text
资产登记或内容发现
        ↓
在调度中心创建任务
        ↓
选择执行方式与 Agent
        ↓
Extension 打开目标页面并采集
        ↓
云端校验、去重、AI 判断与保存
        ↓
内容分诊 / 关注博主 / 官方账号评论 / 舆情巡查
        ↓
人工决定：继续观察、标记误报、归档、转工单
        ↓
分析看板与报告
```

这条链路有四个必须遵守的原则：

- **资产管理和任务执行分开**：关注关系、官方身份、社交账号资料是资产；是否现在执行由调度中心决定。
- **自动采集和人工处置分开**：系统可以采集、提示和分析，但不会代替运营人员把内容直接变成工单。
- **当前状态和历史快照分开**：当前详情展示最新值，趋势必须读取按时间保存的快照。
- **浏览器执行和云端状态分开**：云端可以排队、记录和恢复任务，但不能把一个正在运行的浏览器页面瞬间迁移到另一台设备。

## 3. 关注博主工作流

### 3.1 适用场景

关注博主用于持续观察普通创作者、行业账号、竞品账号或重点 KOL/KOC 的新动态。

它适合回答：

- 这个博主最近发布了什么；
- 是否出现新的相关内容；
- 最近一次检查是什么时候；
- 是否需要立即安排一次主页巡查。

它不直接回答：

- 官方账号的评论区有没有风险评论；
- 某篇负面帖子近几天声量如何变化；
- 哪个 Agent 当前正在执行该博主任务。

这些分别属于官方账号评论巡查、负面帖子巡查和调度中心。

### 3.2 如何登记博主

推荐从 Extension 的账号页登记：

1. 在小红书或抖音打开目标博主主页。
2. 打开 StarVoice Extension。
3. 进入“账号页”。
4. 确认页面识别到正确的账号名称和主页链接。
5. 使用关注或同步相关功能，把账号加入当前租户。
6. 回到后台“关注博主”确认账号出现。

也可以在后台补充或维护关注关系，但主页链接、平台账号 ID 等身份信息应以实际页面采集结果为准。

### 3.3 如何执行巡查

关注博主页面负责展示关注资产；实际执行统一进入调度中心：

1. 在关注博主页面选择目标。
2. 点击“立即执行”或前往调度中心新建任务。
3. 选择博主巡查任务。
4. 选择单 Agent 或多 Agent 执行。
5. 确认平台、账号、作品数量和时间范围等条件。
6. 下发任务。
7. 在调度中心查看执行状态，在“博主新动态”查看业务结果。

### 3.4 结果与状态

关注博主页面主要展示：

- 博主名称与平台；
- 主页入口；
- 关注状态；
- 最近和下次执行时间；
- 新动态或命中情况。

调度中心展示：

- 任务是否已下发；
- Agent 是否在线；
- 正在执行、排队、需要处理或已结束；
- 失败原因和重试入口。

### 3.5 业务边界

- “关注博主”不是“官方账号”的同义词。
- 同一个平台账号可以先作为关注博主管理，确认属于客户官方账号后再标记为官方。
- 把账号标记为官方，不应删除此前的关注历史、动态和采集记录。
- 只凭昵称相同、昵称包含品牌名或作品正文出现品牌名，不能确认账号是官方账号。

## 4. 官方账号评论巡查工作流

### 4.1 适用场景

官方账号评论巡查用于：

- 打开指定官方账号主页；
- 在明确的发布时间范围内读取近期作品；
- 逐篇读取当前可见评论；
- 将评论样本同步回后台；
- 对评论进行风险、情感、意向和官方回复状态分析。

它的目标是“巡查官方账号作品下的评论”，不是搜索全网包含官方账号名称的作品。

### 4.2 官方账号如何登记

官方账号有两层管理：

1. **业务关注层**：在“关注博主”中把已关注账号标记为官方，用于评论巡查业务。
2. **精确身份层**：在平台管理的“官方账号”中登记平台、完整名称、别名、平台账号 ID、主页链接等，用于判断某条回复或作品是否确属官方。

登记时应优先保存：

- 平台；
- 官方账号完整名称；
- 官方主页链接；
- 平台账号 ID 或用户 ID；
- 可验证的别名；
- 备注和归属品牌。

不要使用“名称包含品牌词”作为唯一官方判断条件。否则会把普通用户、服务商、经销商或无关账号误认为官方。

### 4.3 创建任务

1. 进入调度中心。
2. 点击“新建任务”。
3. 选择“官方账号评论巡查”。
4. 选择执行方式和 Agent。
5. 选择已登记的官方账号。
6. 设置本次最多巡查的作品数量。
7. 设置每篇最多读取的评论数量。
8. 设置发布时间范围。
9. 确认账号主页链接有效。
10. 创建并下发。

当前约束：

- 发布时间范围默认可使用近 7 天；
- 单次连续范围不应超过页面允许的上限；
- 发布时间未知的作品不会自动纳入指定日期范围；
- 没有主页链接时，任务不应下发，应先补全账号资料；
- Agent 必须具备对应平台能力。

### 4.4 为什么必须进入作品详情

账号主页列表通常只能可靠提供作品入口和部分概要，不能保证提供：

- 精确发布时间；
- 完整评论；
- 子评论；
- 当前互动数据；
- 作品是否已删除或不可访问。

因此，时间范围不是只靠列表页目测完成。正确流程是：

1. 从官方账号主页获得候选作品；
2. 进入作品详情；
3. 读取并校验发布时间；
4. 只对范围内作品采集评论；
5. 保存作品和评论结果；
6. 对范围外、日期未知或不可访问的作品记录明确状态。

### 4.5 结果页应区分的数量

官方评论巡查至少要区分：

- **平台显示评论数**：平台页面显示的总量，可能包含回复或平台口径；
- **本次读取数**：本次任务实际读到并通过校验的评论；
- **已入库样本数**：去重后实际保存的评论；
- **风险评论数**：经规则或 AI 判断后需要关注的评论。

平台显示评论数不等于本次已采集数。后台不得把二者混成一个“评论数量”。

### 4.6 常见失败

| 表现 | 含义 | 处理 |
|---|---|---|
| 未配置主页链接 | 无法可靠打开官方账号主页 | 补全官方账号资料后重试 |
| 作品发布时间未知 | 无法判断是否在指定范围 | 不自动纳入，人工核对或补采详情 |
| 详情页未完成加载 | 页面还未提供目标作品数据 | 保留失败原因，稍后重试或换 Agent |
| 作品标识不一致 | 打开的详情不是计划中的作品 | 阻止云端写回，重新定位目标 |
| 读取评论为 0 | 可能确实无评论、评论区不可见或加载失败 | 对照平台显示数和任务日志判断 |
| Agent 离线 | Extension 没有保持心跳 | 任务留在云端队列，设备上线后领取或重新分配 |

## 5. 负面帖子巡查工作流

### 5.1 适用场景

负面帖子巡查用于持续跟踪已经发现的负面内容，包括：

- 点赞、评论、收藏、转发是否增长；
- 评论区是否出现新的风险信号；
- 内容是否被删除或暂时不可访问；
- 风险热度是上升、平稳还是回落；
- 是否需要转为人工工单。

它不负责替代关键词搜索。发现阶段仍由搜索采集、博主巡查、官方账号评论巡查或人工录入完成。

### 5.2 从内容分诊发起

1. 进入“内容分诊”。
2. 打开一条负面内容详情。
3. 核对平台、原文链接、作者、发布时间和当前判断。
4. 必要时先完成 AI 深度剖析。
5. 进入“舆情巡查”。
6. 如果尚无巡查任务，创建负面帖子巡查。
7. 在调度中心选择一个或多个 Agent。
8. 下发任务并等待快照。

负面内容可以自动触发深度剖析，但是否创建巡查、是否转工单仍应由业务规则或人工决定。

### 5.3 多 Agent 分配

负面巡查可能包含多篇帖子。多 Agent 的正确含义是把工作项拆分后分配，例如：

- 20 篇帖子分给 4 个 Agent，每个约 5 篇；
- 某个 Agent 因风控、离线或页面异常无法继续时，把未完成工作项重新分配；
- 已完成工作项保留结果，不重复覆盖。

多 Agent 不等于多个 Agent 同时重复采同一篇内容。系统应避免：

- 对同一工作项重复写回；
- 失败 Agent 的旧结果覆盖新 Agent 的成功结果；
- 把另一个自动播放的作品误当作目标作品。

### 5.4 快照与趋势

第一份有效采集结果是基线。只有获得至少两份可比快照后，才可以计算：

- 点赞增量；
- 评论增量；
- 收藏增量；
- 转发增量；
- 新增风险评论；
- 增速和热度变化；
- 上升、平稳、回落等趋势。

没有基线或只有一份快照时，应显示“基线待建立”，而不是显示虚假的增长率。

### 5.5 已删除或不可访问

以下页面特征应识别为内容不可用：

- 小红书显示“当前笔记暂时无法浏览”；
- 抖音显示“你要观看的图文不存在”；
- 页面明确提示作品已删除、不存在或不可访问；
- 目标作品 ID 已确认，但详情数据长期无法加载且平台给出删除提示。

识别后：

1. 立即停止继续读取该作品，防止页面自动播放或跳到下一条；
2. 将本工作项标记为“已删除或不可用”；
3. 保留最后一次成功快照；
4. 保存本次检查时间和页面证据；
5. 不把下一条推荐内容写回到原目标作品；
6. 继续处理任务中的其他工作项。

“已删除或不可用”不是采集成功，也不是普通失败。它是一个有业务意义的终态。

### 5.6 舆情巡查看什么

单条内容的舆情巡查页应展示：

- 当前状态和最后检查时间；
- 最新互动数；
- 历史快照；
- 各指标增量；
- 新增风险评论；
- 趋势判断；
- AI 深度分析；
- 已删除或不可用状态；
- 对应任务记录和失败原因。

分析与报告页用于聚合展示：

- 负面内容总量；
- 新增、上升、回落和不可用数量；
- 分平台趋势；
- 风险主题；
- 高增长内容；
- 评论风险变化；
- 处置和工单情况。

## 6. 内容分诊与 AI 工作流

### 6.1 AI 介入的位置

AI 可以参与：

- 搜索结果与当前关键词的相关性筛选；
- 情感与风险判断；
- 评论意图与客资判断；
- 内容摘要；
- 负面内容深度剖析；
- 报告摘要。

AI 不应该：

- 仅因为出现“安全”两个字就判断为高风险；
- 仅因为作者名称包含品牌词就判断为官方；
- 在置信度不足时静默丢弃数据；
- 代替人工自动转工单；
- 修改原文或伪造缺失字段。

### 6.2 内容分诊操作

1. 进入“舆情工作台 → 内容分诊”。
2. 使用平台、情感、风险、身份、状态等条件筛选。
3. 打开详情查看原文、作者、互动、评论和 AI 摘要。
4. 对负面内容查看自动深度剖析。
5. 对非负面内容按需点击深度剖析。
6. 判断后选择：
   - 保持待处理；
   - 进入负面流程；
   - 标记官方已评；
   - 无需操作；
   - 误报；
   - 归档；
   - 转工单。

### 6.3 误报反馈

运营人员标记误报时，应记录：

- 原判断；
- 正确判断；
- 反馈人；
- 反馈时间；
- 必要说明。

误报是后续优化提示词、规则和业务范围的重要样本。不能只在页面改颜色而不保存反馈。

## 7. 工单工作流

### 7.1 什么时候转工单

只有明确需要人员跟进时才转工单，例如：

- 需要客服回复；
- 需要销售联系；
- 需要法务、品牌或公关介入；
- 需要持续记录处理进展；
- 需要责任人和时限。

发现负面、完成采集、AI 判定负面、创建巡查任务，都不等于已经转工单。

### 7.2 转工单

1. 内容在“处理模式”菜单的独立“工单分支”中选择“转工单”；评论在评论详情点击“转工单”。
2. 填写客户外部 Excel 中的工单号码（如有）和转单说明。
3. 选择优先级、处理人或业务队列。
4. 确认创建。
5. 内容继续留在内容分诊，处理模式更新为“已转工单”；可按处理模式筛选或用工单号搜索。

“已转工单”是第五种处理状态，但交互上与四种内容处理模式分叉展示，只有真正创建工单后才能进入。原工单标记位置显示客户 Excel 工单号；未填写时直接提供行内补录，不再打开转单弹窗。工单进展和结案与内容备注统一显示在内容详情的“处理记录”中；不再设置独立的“工单闭环”入口。

### 7.3 工单中必须保留的来源信息

工单不应只复制一个标题。它需要继续关联：

- 原内容和原文链接；
- 作者和平台；
- 当前互动数；
- 评论与风险评论；
- AI 摘要和深度剖析；
- 历史快照；
- 舆情巡查时间线；
- 已删除或不可用状态；
- 转单说明；
- 处理记录。

因此，内容转为工单后，后续巡查快照和跟踪采集记录仍应在工单详情中可见。

### 7.4 结案

处理人员可：

- 记录进展；
- 更新状态；
- 变更处理人；
- 在内容详情中结案。

用户确认结案后，工单状态和内容归档必须在同一个事务中完成。内容从“工作中”移到“已归档”，但不删除原始内容、评论、巡查历史和处理记录。需要再次处理时，先取消归档，再创建新工单。

## 8. 社交账号管理工作流

### 8.1 管理目标

“社交账号”用于回答：

- 每个 Extension 当前登录的是哪个平台账号；
- 账号绑定到哪些 Agent；
- 今天搜索、增强和采集了多少次；
- 是否应继续使用、休息、重新登录或停用。

它不是 StarVoice 后台登录账号，也不是租户成员权限。

### 8.2 账号与 Agent 绑定

支持两种方式：

- **自动识别**：Extension 从当前平台登录状态识别账号，再更新绑定。
- **手动指定**：管理员选择明确的账号与 Agent 绑定。

如果自动识别无法可靠读取完整资料，运营人员应补充：

- 账号名称；
- 平台账号 ID；
- 注册手机号或备注手机号；
- 归属人；
- 备注。

手机号等敏感信息在列表中应脱敏显示。

### 8.3 每日负载

账号负载应至少区分：

- 搜索次数；
- 增强次数；
- 采集运行次数；
- 采集内容条数；
- 失败事件数；
- 当日限制。

系统根据数据辅助提示可用、休息、风险、需登录或停用，但最终处置由运营人员决定。

### 8.4 换租户与旧节点

Extension 更换激活码或租户后：

- 新心跳和新任务属于新租户；
- 旧租户中的历史业务记录仍应保留；
- 旧 Agent 可能长期离线；
- 管理员可以删除或停用无后续用途的旧节点；
- 未完成任务不能无限等待，应重新分配或结束。

## 9. 分析看板与报告中心

### 9.1 数据来源

看板和报告消费已经保存的业务记录、评论、快照、工单和巡查结果，不直接控制浏览器执行。

### 9.2 典型指标

- 相关内容量；
- 正负面结构；
- 风险内容量；
- 新增风险评论；
- 负面声量变化；
- 高增长负面内容；
- 已删除或不可用内容；
- 工单创建、处理中和结案数量；
- 分平台趋势；
- 官方账号评论风险；
- Agent 与社交账号负载。

### 9.3 报告类型

报告中心支持按当前页面提供的能力生成日、周、月等报告，并提供预览或发送入口。发送前要确认：

- 租户；
- 时间范围；
- 数据是否已经完成处理；
- 收件人配置；
- 报告中的“当前值”和“增量”是否来自可比快照；
- 是否包含敏感信息。

## 10. 桌面与移动端职责

### 10.1 桌面端

桌面端是完整操作入口，适合：

- 创建和分配复杂任务；
- 管理多个 Agent；
- 配置官方账号和社交账号；
- 进行内容分诊；
- 查看复杂详情、趋势与报告；
- 处理工单。

### 10.2 移动端

移动端通过后台的移动布局访问，主要适合：

- 查看今日摘要；
- 查看任务和监控状态；
- 快速处理内容；
- 查看关键指标；
- 进行轻量操作。

移动端复用了部分桌面业务组件。复杂配置、批量编排、大表格和深度诊断仍优先使用桌面端。

## 11. 状态口径

### 11.1 任务状态

| 状态 | 业务含义 |
|---|---|
| 等待执行 | 已创建，等待 Agent 领取或开始 |
| 排队 | 已分配给 Agent，但前面仍有任务 |
| 执行中 | Agent 已领取且正在处理 |
| 已暂停/中断 | 当前不能继续，需要恢复或人工介入 |
| 需要处理 | 已结束但有失败、部分失败或人工问题 |
| 已完成 | 所有预期工作项均已结算 |
| 部分完成 | 已完成一部分，剩余部分失败或不可用 |
| 已停止 | 用户主动停止 |
| 历史 | 已归入历史展示，不代表删除数据 |

### 11.2 工作项状态

| 状态 | 业务含义 |
|---|---|
| pending | 尚未执行 |
| assigned | 已分配 |
| running | 正在执行 |
| succeeded | 成功写回目标结果 |
| failed | 执行失败 |
| skipped | 按规则跳过 |
| unavailable | 目标已删除或不可访问 |
| stopped | 随任务停止 |

页面中文文案可能按业务场景显示，但不能把 `unavailable` 隐藏成普通成功，也不能把 `skipped` 当作采集失败。

## 12. 当前稳定边界和测试中能力

### 12.1 当前可用

- 关注博主资产管理和新动态展示；
- 调度中心创建、分配、继续、停止和查看任务；
- 单 Agent 与多 Agent 工作项编排；
- 官方账号评论巡查；
- 已知负面帖子的快照跟踪；
- 内容分诊、误报、归档和人工转工单；
- 工单中查看来源信息和巡查记录；
- 社交账号绑定与每日负载；
- 数据看板与报告。

### 12.2 Beta 或仍需持续验证

- 调度中心整体仍标记为 Beta；
- 平台页面结构变化后的自动化稳定性；
- 抖音风控、验证码、安全提示和自动播放处理；
- 小红书、抖音删除页的全部变体识别；
- 多 Agent 失败转移和边界竞态；
- 社交账号自动识别的完整率；
- 移动端复杂表格和大型配置界面；
- AI 高峰期队列、超时和降级体验；
- 报告邮件依赖租户收件人与发送配置。

### 12.3 当前未实现或不应承诺

- 浏览器正在执行时的无缝实时迁移；
- 不打开浏览器和 Extension 仍能由云端直接采集平台页面；
- 只靠昵称自动确认官方身份；
- 任意平台页面变化后仍保证零维护；
- 自动解决验证码或绕过平台风控；
- AI 判断百分之百准确；
- 自动把所有负面内容转成工单；
- 只有一份快照时计算真实趋势；
- 将平台显示评论总数等同于已采集评论数。

## 13. 运营验收清单

每次新增或修改巡查流程，至少验证：

- [ ] 当前租户正确；
- [ ] 目标账号或内容身份准确；
- [ ] Agent 在线且平台能力匹配；
- [ ] 任务类型、时间范围和数量上限正确；
- [ ] 多 Agent 分配没有重复工作项；
- [ ] Extension 出现深色任务状态页；
- [ ] 任务中心能看到真实进度和失败原因；
- [ ] 目标作品校验通过后才允许云端写回；
- [ ] 删除或不可访问内容不会串到下一条推荐；
- [ ] 平台评论数、本次读取数和入库数分开显示；
- [ ] 负面巡查至少两份快照后才显示增量；
- [ ] 工单必须由人工明确创建；
- [ ] 工单详情保留巡查快照和历史；
- [ ] 失败任务可以重试、重新分配、移到历史或清理；
- [ ] 移动端能完成关键查看和轻量处置；
- [ ] 报告时间范围、收件人与指标口径正确。
