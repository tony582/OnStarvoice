已用发布源码在隔离 VM 复现：

1. 关键词进度先含搜索页 runnerTabId；后续 streaming_sync_done 没有该字段，progress reporter 把它置空。终态沿用空值，主页收尾无法找到搜索源页。
2. `isHome` 只接受抖音根路径，不接受现场实际 `/jingxuan`；`isPlanSearch` 未接受实际小红书 `/search_result/` 尾斜杠。
3. 缺少源页或 MV3 worker 重启后，旧逻辑另建/复用主页并结清队列，搜索页永久残留。
4. 已有主页时，旧逻辑仍优先将搜索页导航成另一个主页。
5. 每 window/platform 仅保存最新一条记录，会覆盖较旧源页的收尾义务。
6. 同 URL 文档替换与最后 idle 检查期间出现主页的并发场景缺少复核。

旧的 100 轮测试未携带真实搜索源页；后台重启测试甚至把“保留搜索页并新建主页”当作预期，不能证明现场标签数收敛。这轮需要真实源页、进度丢失、文档变化和后台重启的组合测试。

## 补详情故障证据与合并修复

用户截图中 21:32:56、21:36:00、21:39:56、21:43:52、21:45:36 的任务均来自 Windows~地球。生产原始 attempt 是 `TARGET_RUNNER_TAB_TIMEOUT`，发生于作品采集页启动阶段；没有 targetResults、同步尝试、正式记录或任务 observation。界面的 `detail_finished_without_ingestion` 是最终投影，不能代替根因。21:53:49 创建的后继任务成功取得正式记录和 observation，说明该节点并非永久不可用。只读比对的六个生产关键文件与 d68201d 相符。

1. 仅手机发现作品补详情采用最多 60 秒观察同一个目标页，并在计时器暂停恢复后做一次有界最终检查。不刷新、不开第二个页、不重跑采集。核验目标作品、实际 URL 和文档身份，页面内容已就绪时无需等待无关资源全部结束。取消、页面关闭或身份变化停止观察，登录/验证码/安全限制继续按需处理并保留现场。其他定向任务仍走原 20 秒路径。
2. 同租户同节点最新三次严格绑定 attempt 的补详情执行，如果均在 15 分钟内出现原始打开超时，按最新执行第一次服务端回执计 5 分钟冷却。重复心跳不续期；真实入库成功打断连续失败；候选保持 queued，健康节点可领取；到期走已有执行槽锁，只允许一项探测。不会主动重试历史失败或暂停手机巡查。
3. 冷却只读查询放在独立 savepoint 内，最多 750ms，并保留调用方更短期限。查询失败恢复事务及原超时，仅放弃本次附加冷却，避免阻断普通派发；真实断连或回滚失败仍抛错。
4. 服务端继续保留 `detail_finished_without_ingestion` 等稳定外层错误码，同时保存和显示原始 code/message/已有 phase。未拿到正式入库回执时 successCount 为 0；迟到的真实回执可按现有规则结清并移除过期诊断。取消和人工归档语义不变，无需改 Admin。
