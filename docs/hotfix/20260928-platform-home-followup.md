## 现场证据与代码复现

2026-09-28 用户截图显示抖音搜索页与 `/jingxuan` 主页并存。附带诊断明确是 0.4.20；最近关键词、手机补详情任务已有完成记录。诊断里的历史错误及约 24.65 小时旧的页面 runtime 不能直接作为当前故障依据。用户明确说明调试提示条来自其他 Edge 正在采集，是正常情况，不作为本次缺陷、不修改 Debug/session 流程。

本机实际加载的 `extension-build` 104 个文件与 d68201d 逐字节一致。

已用发布源码在隔离 VM 复现：

1. 关键词进度先含搜索页 runnerTabId；后续 streaming_sync_done 没有该字段，progress reporter 把它置空。终态沿用空值，主页收尾无法找到搜索源页。
2. `isHome` 只接受抖音根路径，不接受现场实际 `/jingxuan`；`isPlanSearch` 未接受实际小红书 `/search_result/` 尾斜杠。
3. 缺少源页或 MV3 worker 重启后，旧逻辑另建/复用主页并结清队列，搜索页永久残留。
4. 已有主页时，旧逻辑仍优先将搜索页导航成另一个主页。
5. 每 window/platform 仅保存最新一条记录，会覆盖较旧源页的收尾义务。
6. 同 URL 文档替换与最后 idle 检查期间出现主页的并发场景缺少复核。

旧的 100 轮测试未携带真实搜索源页；后台重启测试甚至把“保留搜索页并新建主页”当作预期，不能证明现场标签数收敛。这轮需要真实源页、进度丢失、文档变化和后台重启的组合测试。

## 修复边界

- 搜索源页身份独立于展示进度，绑定真实任务/轮次/页面/文档；页面是否新建由后台实际创建结果决定。
- 真实搜索导航稳定后旁路记录 URL/文档；记录失败不阻断采集。
- 只对精确证明属于任务且已安全结束的页面做收尾；保护用户切页、登录验证、新任务、待上传与原始用户页。
- 识别真实平台主页，优先复用；未知来源不以新增主页冒充清理成功。
- 定向任务已安全关闭自己创建的平台页时，仍需保留原有主页归位能力，不因关键词修复造成退化。
- 不调整采集解析、过滤、关键词预算、重试、派单、数据库、手机 Runner 或调试会话。
- 用户已确认这些是专用采集窗口，任务停稳后每个平台仅保留一个主页。只对实际绑定并导航的任务来源页授予此收拢权限；没有完整证据的旧页不按域名追认。
- 修正版准备为 Extension 0.4.21，Android Runner 仍为 0.2.6。
- 本次尚未对正在运行的浏览器执行关页、重载或升级。
