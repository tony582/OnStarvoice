# Extension 0.4.24 · 新旧界面兼容发布

分支：`codex/extension-ui-refresh`。UI 提交：`8d65418`。

## 发布范围

- Extension：仅新增可选界面层与原界面导航/提示接线，manifest 版本升为 0.4.24；权限不变。经典默认，配置文件内手动开启新版，可切回。
- 服务端仅三份发布元数据：`server/routes/update-manifest.js`、`server/public/about.html`、`server/services/ops-control.js` 的版本常量。没有业务 API、数据库迁移、Admin、任务协议或调度变更。
- 只重启 `onstarvoice-api` 使更新公告生效；不重启 scheduler、ai-media、手机 Runner 或 Extension，不派发/停止采集。API 会有短暂重启窗口，不能称为零中断。
- `minSupportedVersion` 保持 0.3.51，旧 0.4.23 下载保留；不强制旧节点升级，新旧节点可连接同一套服务。禁止在同一浏览器配置中并装两份扩展。

## 发布前证据

- 线上最新版本确认为 0.4.23；下载包 108 个文件与本地源比较，仅两个已修改的界面文件不同。92 个受保护代码文件未变，manifest 除版本外未变。
- 线上三份元数据 SHA-256 与本分支修改前完全一致，避免覆盖别的发布。当前生产不是 Git checkout，以逐文件 SHA-256 和公开下载包为基线。
- 169 项 UI/采集接线测试、37 项更新/运维测试、6 项发布脚本测试通过；浏览器 50 项多关键词 / 41 项笔记页检查已通过。
- 发布脚本执行白名单、基线漂移、同名包、互斥锁、备份、API 健康、更新清单与下载哈希检查；失败回滚演练通过。旧包不删除，备份和发布回执保存在服务器独立发布目录。

## 节点使用与边界

1. 安装更新前确认该节点空闲，已有结果安全保存；保持原 Extension 身份和目录，不清浏览器存储。
2. 安装后仍为经典界面。右上角菜单 → 试用新版界面；新界面设置 → 切回经典界面。只是 UI 切换时不重载、不停止任务。
3. 本机 extension-build 更新文件不代表所有 Chrome/Edge 已重载。浏览器运行版本以节点心跳为准；实际升级需在空闲时重载，不能中断正在采集的节点。
4. 真实采集、同步和 CPU/内存对比仍未做完。首个空闲节点先试用，观察实际回执后再扩大；后台健康与包可下载不能当成业务验收。

部署后的准确提交、包哈希、进程前后状态及回滚目录以本次发布回执为准。
