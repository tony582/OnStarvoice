分支：`codex/research-wechat-articles-20261109`。状态：开发候选，T13 已由 Claude 真机复测通过；T14 修正域名 OCR 和留言质量，离线验证见第八轮，新版真机复测由 Claude 执行，未部署。本轮是既有视频号采集链路上的文章适配，不另建调度或入库系统。首次发现使用手机「发现 → 搜一搜 → 文章」；电脑读取链接中的网页文章头、正文和图片地址，手机确认文章页、复制链接并补采文末留言及指标。已有文章巡查使用保存的原链接，经微信「访问网页」打开，再复制链接核对，不按标题重新搜索。

## 与视频号实现的复用关系

分支继承已部署的 `2953bd8`（链接优先巡查）、`97583fa`（手机 0.4.7）、`1ade51e`（多选转发）和 `dcb5d11`。视频号原深链、预览和转发保留既有行为。

| 范围 | 复用方式 | 文章必要差异 |
| --- | --- | --- |
| 筛选 | 同一 `WECHAT_SORT_OPTIONS`、时间范围选项、排序锁定规则；服务端同一 `mobileTaskFilters` 微信分支 | 文章不开放未校准的时长/范围选项 |
| 手机生命周期 | 同一微信 adapter 工厂、设备检查、输入法恢复、待完成动作、停机与关闭证明 | 配置文章 flow 和方法列表 |
| 电脑正文 | 同一 `createSharePreview` Chrome 进程、队列、超时、取消和关闭 | 文章读取渲染 DOM，不使用视频号 Finder API；真实结果与后续验证范围见第六至八轮 |
| 执行控制 | 同一 `BudgetLedger`、`OperationGate`、`DeviceClosureJournal`、任务身份校验、停止结果、AI 预筛及帖间等待 | 手机留言分段返回；显式 OCR 诊断模式的正文与回顶动作仍受同一时限控制 |
| 调度 | 同一节点注册、领取、续期、手动/定时/弹性编排和负面巡查 | 平台 `wechat_articles`，能力 `wechat_articles`；旧节点不领取 |
| 上传 | 同一 SQLite outbox、批次与回执重放，原 `/agent/posts` 和回执接口 | 事件 `wechat_article`，按 eventKind 分批 |
| 入库 | 原 post ingest → sync → record store → 评论工作流 → 观察记录/回执 | 分派文章字段校验；身份来自规范化文章短链接 |
| 后台 | 原任务编排、节点列表、分诊、记录详情、留言列表、报表 | 文章增加正文完整性、留言可见状态、阅读数及未知值说明 |

视频号的预览策略接受 `sph` 链接并监听 `get_feed_info`，取得 `dynamicExportId` 后用 Finder 专用深链打开作品。文章在同一个预览组件增加 DOM 策略，不伪造该标识，不通过猜测深链打开，也不创建新的浏览器采集体系。

## 采集与完整性

- 保存实际可见标题、公众号、作者、发布时间及精度、地区、正文、阅读/点赞/分享/推荐、文章链接和文末可见留言。
- 当前支持的规范链接是 `https://mp.weixin.qq.com/s/<token>`。去除跟踪参数后计算独立 `wxa_` 身份；不同标题或相同作者/时间不代替链接身份。
- 电脑正文优先：只读取渲染 DOM 中的标题、账号、日期、段落和正文内有序图片链接；不读取账号凭证或隐藏接口数据。网页与手机复制链接必须规范化后完全相同。网页拒绝、验证页、折叠正文和无法确认的页面均明确报告，不静默切换访问路径。
- 已读文章可能恢复旧位置。正常 page_dom 路径确认文章 activity，排除结果页及聊天选择页；工具栏隐藏时最多内区短拖一次让菜单露出，不找手机文章头、不回顶。没有菜单文字时，须经多次读屏取得连续正文证据才确认页面；按校准菜单坐标操作后仍核对菜单标签和新鲜复制链接。复制链接后，网页标题和公众号与搜索卡片沿用既有匹配规则核对；标题、公众号、作者、发布时间及地区均以网页为准。链接巡查必须同时满足保存链接、手机复制链接与网页链接规范化后一致。
- 网页身份及时间范围核对通过后，core 才把带规范链接的文章头交给手机。手机要求本次复制链接成功且与网页文章头绑定，从当前位置向下分段滚到配对「阅读／不喜欢」或左侧独立「留言 N／留言」标题，再读取留言；锚点必须进入安全读屏区。没有阅读数保持 null，裸留言标题不推断为 0 条。手机不再解析文章头或累积正文，网页失败不自动回退到手机 OCR。
- 手机 OCR 正文保留为显式诊断模式，逐屏核对重叠并按文档位置合并，避开浮层。单次最多 8 屏，总计最多 80 屏、10 万字符；不能把诊断模式单独通过当成电脑正文联合路径验收。
- 评论关闭、任务未启用评论、没有留言入口和留言为空是不同状态，均不阻断正文。不能把没有入口解释为评论总数 0，也不把“关注后可留言”解释为禁止读取已有留言。
- 留言包含可见回复；最多展开 3 处回复，未展开或未确认读到底会保留部分状态。不会关注、点赞、评论或向联系人发送消息。
- 留言作者 OCR 变化时，仅在可识别地区、有效时间一致，且正文高度相似或互相包含时跨作者合并；回复还必须属于同一父留言。原同名重叠规则继续复用。单个符号或已确认的误识别「总」保留正文、作者留空并标记 `authorUncertain: true`；遇到后续可靠名字可更新。广告由右侧小号标记和同一行的实际位置分段，不按品牌词删留言。细节、入库保护和回放限制见第八轮。
- 没显示的互动数是 `null`；`10万+` 等原文与精度一并保存。发布时间按页面分钟/日期精度记录。指定时间范围时，未知时间或跨范围边界的模糊时间不纳入该次任务。
- 网页正文、每个互动指标和手机留言分别记录来源与采集时间；网页/手机无显示数字时保留未知。只保证记录采集时显示值，不保证平台实时统计一致。
- 网页图片保留 DOM 顺序和真实链接，交给既有媒体存储；发现 URL 不等于文件已保存。文章最多保存 100 个去重图源 URL，其他平台仍为 20。依据用户提供页面中的实际图源，只增加 `qpic.cn` 白名单和微信 Referer，不扩大到 `qq.com`，不改 URL 尺寸或参数。文章文件经过完整格式结构及实际大小／尺寸检查（>10 KB 或宽高均 >100，最多 8 MB）；这不是像素解码，也不证明 CDN 提供了最高分辨率。暂不支持 BMP RLE 等压缩变体。
- 图片入库、后台下载、按需识字继续复用既有链路。同记录文章下载顺序执行，旧正文或旧本地映射的任务不能覆盖新状态。`evidence.imageStorage` 记录当前已发现图源去重后的 `expected/stored/checkedAt`，仅全部已发现文件通过校验并保存时 `originalImagesCaptured=true`；不能据此抬升正文完整性或断言未漏图。采集时的观察记录不在下载完成后改写。正文图片按 `bodyBlocks` 原顺序展示，并保留原图 URL 作为识字引用；识字仅由用户点击触发。Claude 已提供 42 张图的独立真实下载结果，不能等同于产品存储链全部落盘；真实图中文字识别尚未验收，详见第六轮。
- 关键词任务的普通单篇网页失败记录 `wechat_article_page_failed` 和 `pageFailures`，本篇不入库、不读手机留言、不记成功链接，返回列表继续。自然结束有失败时为 `completed_with_warnings/article_page_incomplete`。网页标题／公众号不匹配的卡片按 `article_identity_unverified` 跳过，沿用最多连续 4 次的既有恢复预算。预算、取消、租约和不确定设备操作仍保留原终止原因；验证页、链接不一致及单篇巡查失败仍停止。没有网页失败自动转手机 OCR 的分支。
- 再次采集不完整时保留此前更完整的正文及其标题、账号、时间和证据；本次观察单独保留，不把历史已知指标伪装为本次可见数字。
