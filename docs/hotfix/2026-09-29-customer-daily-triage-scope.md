# 客户日报沿用内容分诊准入规则

日报的采集汇总、热榜和缺失发布时间提示原先只排除 AI 判为无关的内容，未调用分诊的哨兵品牌证据准入判断，也未统一使用人工相关性。因此未获分诊准入的哨兵帖仍可能计入月累计和热榜。

所有日报取数路径统一复用现有 `recordTriageAdmissionSql`、`recordEffectiveRelevanceSql` 和关注规则。处理清单也使用同一日报谓词，保留已有处理事件口径。非哨兵范围的信息不足帖仍按分诊规则处理；关注不能绕过哨兵准入；人工确认相关可进入。归档本身不取消已入库贡献。

采集时间边界、按帖去重的月累计、处理日期统计、客户填写内容及已有冻结版本不改变。新生成的版本根据同一分诊范围重新取数，不能以删除单个热榜条目代替修复汇总。此改动不需要更新 Extension 或手机 Runner。

验证：124 项日报单元回归；新增真实 PostgreSQL 场景覆盖缺品牌证据、历史采集关键词、人工相关/无关覆盖、关注例外、归档、非监控、跨租户，以及重新生成不改变旧快照。发布仅替换 `server/services/customer-daily-report-data.js`；先比对精确旧摘要，保留备份，在采集自然空闲后重启服务并验收。不会发送邮件或飞书消息。
