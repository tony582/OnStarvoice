## 发布顺序

1. 核对候选提交与包哈希，确认对应 CI；只读复核生产受影响文件仍等于本轮基线。若不相等，停止切换并重新合并差异。
2. 取得生产数据库有效备份和应用目录回滚副本，验证可读取。只读查询 `schema_migrations` 与一次性回填标记；计划外待执行迁移或回填必须先查清，不能直接运行旧批量部署脚本。
3. 从当前生产目录准备同文件系统 staging，只覆盖产物清单中的文件；保留现有环境配置、依赖、媒体与上传目录。新功能默认关闭，保留旧包下载。
4. 仅本次新增迁移按顺序应用：`086_capture_discovery.sql`、`087_android_control.sql`、`088_discovery_detail_jobs.sql`、`089_discovery_ui_binding.sql`。前三项添加发现账本、索引和幂等重处理表；089 仅扩展新账本的验证类型约束。它们不创建巡查计划或批次，不删除业务记录。控制锁等待与语句时限；任何异常先回滚该事务。
5. 按项目现行原子目录切换流程替换应用并重启 `onstarvoice`，等待就绪后校验健康、版本、包下载 SHA-256、迁移登记和调度页。不要用旧 `deploy/deploy.sh` 做全量同步。
6. 仅将指定 OnStar 租户 UUID 加入 `ANDROID_DISCOVERY_INGEST_TENANTS`。旧 0.4.12 浏览器没有 `discoveredPostCaptureV1`，不会领取新补采；只升级指定试点节点。生产 DNS 先保留 `system` 默认模式，不把 Mac 的测试用 Google DoH 设置复制到服务器。
7. 在专用私有状态目录注册当前手机（序列号 829d89），不复用已注销的 localhost 测试凭据。Runner profile 使用 `douyin-40.6.0-de106-api27-p0`；精确匹配设备、抖音版本与已校准选项后才允许搜索。`productionAccepted=false` 保留，直到试点业务验收完成。
8. 核对新版 Extension 心跳和新手机节点的实际绑定，然后下发 1 词首批，核对作者／正文／类型、去重、评论回执、自动关页、待传为零、正常停稳。失败记录保留，按明确原因处理，不默认无限重跑。

## 回滚

先在 0.4.13 控制面停止新增任务，对手机试点运行发出整批停止，待原手机动作、租约、补采页面和在途上传结束，核对 `deviceHeld=false`。不能把超时或进程退出当作停稳证据。

完成停止后再移除租户开关并停止专用 Runner，恢复应用回滚目录与旧扩展 0.4.12。新增账本、索引和已采集记录保留；常规代码回滚不运行 DROP／reset 迁移，也不恢复整库覆盖上线后的正常业务写入。数据库备份仅供真正的数据事故按专门恢复流程使用。

回滚后检查 PM2、健康、调度查询及原 PC 采集节点。手机不自动转到其它设备，也不自动创建新的晨巡计划。首次试点将 0.4.13 从独立目录加载到指定 P0 浏览器；主工作区生产 `extension-build/` 保持原样。以后只有用户明确批准正式替换该目录时，才先备份旧目录、从对应发布提交构建并核对 Reload。
