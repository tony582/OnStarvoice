## 对抗式复审

本会话逐路径复审并以反例测试验证，未把先前评审的 PASS 当作本次结论。

- **页面归属**：只关闭后台核实创建的详情工作页或精确请求/轮次的运行页。检查 url 与 pendingUrl、用户焦点和当前请求；没有归属的冻结页也不能 discard。通用资源清理在 S2/S3 下保留全部工作页，关闭动作只由前面的归属检查执行。
- **证据与互斥**：时间过去、终态台账或后继任务都不是停止证明。保留中继轮次隔离及本机执行锁，旧轮次未证明停止前不启动第二条流水线。
- **上传**：发现原代码会在取消时清空队列、把处理失败算作已上传、在无回执时强关运行页，均已修复。退役先停止采集生产者，再等待全部入队结果获确认；迟到记录进入同一队列，临时网络失败保持原任务身份自动重试。未结清不能关页或放锁。
- **服务端身份**：迟到 canceled 快照不能抹掉围栏、状态或 control_task_id；否则下一轮核对回执会因 ID 不一致被拒绝。集成测试覆盖这个实测发现。
- **轮询成本**：等待下一核对轮次时，心跳不会重复执行重的围栏领取查询。SQL 计数断言已通过；5,000 行本机临时样本的基线与当前预检均使用 tenant/status/updated_at 索引。已有约 275 ms 的停稳锁判定 SQL 未增加到新的轮询位置。本机 EXPLAIN 不是生产延迟承诺。
- **S4**：复用 F3 判定和事务结算；整棵任务树出现停止围栏、人工/平台安全标记或活跃工作时不自动结算。次数用尽的手机批次结算后仍在需处理时，事件文案不再谎报“移到历史”。
