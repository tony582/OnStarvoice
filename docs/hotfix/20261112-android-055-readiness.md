# Android 0.5.5 候选：就绪检查与验收

本说明记录候选行为和验收口径，不表示生产已升级。生产 0.5.3 保持原启动器、状态目录、关键词与计划。

## 修复范围

- 本机 ADB 服务启动使用 `adb -P 5037 start-server`；其它命令保留固定主机、端口和设备序列号。恢复时限、取消与冷却不改变。失败诊断仅保留有界分类，不写原始输出全文。
- 微信预览先加载采集器提供的临时 `127.0.0.1` HTTP 网页，自检上限 10 秒。失败后最多另等 2 秒确认自有浏览器退出；确认退出且系统 Chrome 可用，才在本进程回退、提示一次并记录诊断。显式 `--chrome` 失败不自动回退。
- 不修改解压、签名或隔离属性。相同官方压缩包的 Python 与 ditto 解压结果已逐项比对为零差异。

## 识字与启动器口径

实际 OCR 回收事件名为 `ocr_helper_recycled`。验收还须分别记录连续三次快速失败后的单次回收、120 秒内再次失败不重复回收、真实任务开始前补预热；不能用假回复或单项模块测试代替真机端到端结果。

启动器命令为 `exec caffeinate -is node cli.mjs up ...`。本机 `ps` 观测的父子关系可以是运行任务的 node 为父、caffeinate 为子，应以 PID/PPID 原始输出及一起退出的生命周期证据判断，不能仅从命令顺序反推方向。2026-11-12 的独立 3 秒示例实际为 `/bin/sleep` PID 98242 → `/usr/bin/caffeinate` PID 98243；它只证明本机工具的进程形态，不是新一轮采集器验收。
