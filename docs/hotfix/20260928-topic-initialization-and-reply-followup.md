# 历史主题初始化、回复继承及筛选布局

基于已上线的 `7fc5581` 继续修复 Server 与 Admin，Extension 和依赖保持现有版本。

## 日报回复继承

客户先填写回复、标为“已回复”，后改成“评论区留言”但没有再填备注时，原回复仍属于同一处理过程。两种状态之间的更正沿用最近一次明确填写的状态变更回复，并保留同一过程内的独立、同状态和批量补充备注。明确填写了新回复时优先使用新内容；转到待处理或其它状态后结束原过程，后续回复不混入旧备注。

跨月更正只为清单中的相关帖子补查早期回复和备注，不把旧事件加入当月统计。原有日报版本保持不变，新生成版本使用继承规则。

## 七类主题及历史初始化

客户确认内容主题必须在七类中单选，监控范围外也归“其它通用相关”。新提示词版本为 `record-topic-v10` / `saic-gm-content-topic-v2`。该业务归档不修改独立的相关性、情感、意图或处理状态。

筛选和人工修改只提供七类，不提供“未分类”。采集后尚未完成 AI 的短暂空值显示“主题生成中”，不是第八类。旧 API 空值筛选保留兼容，人工主题不能清空。

历史初始化使用 `server/scripts/initialize-content-topics.js`，必须显式指定租户，默认只读试分；带 `--apply` 才回写。通过现有 DeepSeek 接口分批分类，要求每条都有合法且唯一的七类结果，错误批次重试后仍失败则保留空值并报告，不以批量默认值代替分类。回写仅限仍为空、无人工主题覆盖、正文及逐字稿未变的记录，保留客户的情感、处理状态、备注和其它 AI 判断。按租户加运维锁，成功结果可续跑，保存主题依据、运行标识和汇总审计。

本次无数据库结构迁移。历史更新前另存原主题及相关 AI 字段，以便逐条核对。

## 筛选栏

缩短搜索输入，完整搜索范围保留在提示中。内容主题移动到第一排，第二排恢复原有网格列数对应的控件数量；主题使用和相邻筛选器一致的浅灰底色。移动端保留折叠筛选入口。
