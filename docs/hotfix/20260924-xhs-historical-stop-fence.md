# 小红书历史停止保护误拦修复

本地修复已验证，尚未提交、推送或部署。基线为 `3043c9c82252901a9d1c643a6def409e0c140cdd`。仅需发布 `server/services/capture-cloud.js` 和 `server/routes/capture-cloud.js`，无数据库迁移或 Extension 更新。

## 故障和证据

2026-09-24 早上，新加的 `PREVIOUS_CAPTURE_STOP_UNCONFIRMED` 占用判断将历史 `superseded` 任务也视为节点仍未停稳。它只识别取消、成功完成或 `recoveryTaskId`，遗漏了历史自动接力及原节点后续执行已经结束的证据。

备份中共有 49 条记录，涉及 8 个小红书节点；旧记录更新时间从 9 月 2 日至 23 日。07:14:22 的 `historical_stop_fence_reconciled` 事件解除这些占用，07:14:26 即重新出现下发事件。相关服务端源文件 SHA-256 与 `3043c9c` 一致；服务器根目录和 server 目录内的旧 RELEASE_COMMIT 文件并未同步更新，因此不能以这些旧标记判定本次运行版本。

## 修复后的判定

仍保留历史错误。仅当以下证据同时成立时，旧记录不再占用节点：

- 旧任务已被替代，没有待确认的停止操作，且存在同租户、同父批次的真实接力任务。
- 原节点在相同平台上又创建并实际启动了更晚的采集，创建与启动时间均晚于旧记录最后更新。
- 后续采集已经成功结束；若后续采集是取消状态，必须有同节点、同任务已接受并完成的停止指令回执。

配置保存、打开页面、父任务汇总、其它节点或租户的完成记录不作证明。当前未确认的停止、正在执行的任务和未完成指令继续占用节点。工作项重试策略保持原样，不因历史节点放行重启旧任务。

调度领取、心跳交付、手动下发排队原因及公平调度共用此规则。证明数据按租户和节点汇总一次，避免逐条关联查询造成 JIT 编译及重复扫描开销。
