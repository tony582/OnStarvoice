# 小红书时间窗 Hotfix

分支：codex/hotfix-xhs-time-window-20260910
基线：e91f93dfed81067b609cc5fa963e9702de6f53c5（与已核对线上 0.4.7 采集源码一致）。

## 已核实原因

2026-09-10 的小红书关键词普通采集确实带有 publishTime=day，但既有调用只尝试点击筛选，没有强制确认时间项仍选中及结果完成刷新。最终入库的旧帖不是负面巡检混入。另有一例没有日期节点的卡片，把标题“9-10月”解析成上一年日期；这与真实旧帖是两个问题。

## 修改

- 仅小红书关键词采集选择 day/week/month/halfyear 时，确认时间项最终选中及结果更新证据。无法确认则当前关键词失败、继续后续关键词；已有安全页面处理保持原规则。
- 结果变化接受 ID 更换、节点实际替换和清空/加载后稳定，不把延迟结束或追加尾部当作筛选生效。观察器最多额外等待约 8 秒，并清理监听。
- 列表日期优先来自日期节点，不再从卡片标题/正文猜测。作者行兼容日期保留来源标记，昵称末尾日期不用于强制排除。
- 对确定超过所选范围的发布日期，在增量同步和最终列表应用同一时间窗。边界日、未知/矛盾日期保留；全过期正常按 0 条结束，不增加滚动上限或重搜。
- 未修改抖音、无时间限制、单帖、巡检与实际运行的 extension-build。

## 验证

- Node 24.12.0：2,039 项全量回归通过。
- Node 18.20.8：2,039 项全量回归通过。
- 扩展快照校验、语法与差异检查通过。
- 原项目 extension-build 的 content-v2.js、capture-sync.js、keyword-search.js SHA-256 与修改前一致。

当前仅本地修改及测试；没有重载在线浏览器、推送或部署。测试覆盖模拟页面/结果生命周期，真实小红书页面仍需在专用测试节点验收后再发布。日期来源不明确时保留内容；筛选结果不能证明刷新时会跳过并报告该关键词，避免把旧列表当作新结果。

## 后台入库时间校验（小红书与抖音）

用户补充要求：后台入库时再次核对发布日期，并严格跟随本次选择的范围；半年内允许最近半年，不限时间不拦截。

- `record-store` 在事务内读取同租户采集任务保存的 `planSnapshot.searchFilters.publishTime`，要求平台、关键词与关键词采集类型一致。仅 day/week/month/halfyear 启用窗口；all/未设置保持不限，未知参数不解除以前的拦截。单帖、巡检、导入等原路径保留。
- 时间窗锚定任务 `started_at`（缺失时 `created_at`），不按上传时间滚动。日期精度保留上海时区的整天、整分钟或整秒边界。详情日期优先于列表，不将正文、缺失日期、`lastEditedAt` 当作发布时间。
- 详情无年日期使用其自身可信采集时间求最晚可能日期；编辑日期只证明发布时间不晚于编辑时间。二者仅存独立时间上界，只有整个上界早于窗口才排除，绝不写成精确发布时间。跨年和日期不明时保留未核验结果。
- 明确超期的新帖不创建 `records`、观察、评论、AI 或媒体任务；写入 `capture_task_events`，响应 `capture_publish_time_out_of_range`。详情后来揭示旧日期时，仅将该轮新建且未人工修改、未处置、未被其他任务接收的记录移出客户清单，保留原始证据。旧任务尝试必须先通过既有归属校验。
- 普通回传与迟到预筛结果不能重新放开已确认旧帖；不同年度也不重推已保存的日期上界。新任务放宽为半年或不限时，符合新范围的内容恢复原业务处理。缺少任务关联的真正新采集以新采集时间区分于原上传重放，沿用原不限路径。
- 客户端将该专属结果计为“超出时间范围已排除”，不计成功或网络失败，不重试、不触发客资，并沿用现有排除计数完成任务。手动历史同步不继承另一个活跃任务的范围。真正重新采集可使用新范围；普通去重与同步行为保留。

验证使用独立本地 PostgreSQL 测试库，覆盖单条/批量上传、严格边界、半年与不限切换、人工与历史保护、并发回传、预筛回写、无任务新采集与重放、过期尝试。额外只读提取本次 23 条旧帖的日期与任务证据作离线回放：day 23 条全部排除；halfyear 排除 12 条、保留 11 条；all 23 条全部不启用日期拦截。未修改生产数据。

服务端与扩展配套交付：旧扩展能收到确定拒绝，但会把它显示为同步失败；本 Hotfix 的扩展才能正确展示排除并完成计数闭环。当前工作树构建只供发布准备，未替换用户正在加载的原项目 `extension-build`。

最终验证：Node 24.12.0 与生产兼容 Node 18.20.8 各 2,070 项回归全部通过；Node 18 下入库窗口、负面巡检结果回放、小红书来源链接共 25 项 PostgreSQL 集成测试通过（其中本次入库窗口专项 14 项）。工作树扩展快照校验通过，独立审查通过。未增加数据库迁移，未更改线上服务或插件。
