# 2026-10-13 手机 Runner 0.3.3：独立筛选弹层与一天内选择

## 故障与证据

用户看到手机展开筛选后始终停在「不限」，没有选择「一天内」。

- 运行的是 `runtime-0.3.2-195fce9`；搜索实现与仓库一致。DE106 上抖音仍是 40.6.0，安装更新时间 2026-09-23。
- 2026-10-12 22:01–22:49 的 13 个关键词共 39 次尝试全部 `search / device_timeout`、0 卡片、0 链接。10-13 00:02 重新启动后仍然复现；当前设备连接、Appium、内存正常，任务参数为 `publishTime: day`。
- 被动日志显示点击「筛选」后连续读屏约 15 秒，没有任何选择「一天内」的点击。屏幕截图却清楚显示筛选面板和「不限」选中。
- 独占校准会话对同一面板读取：`enableMultiWindows=false` 只有 57 个节点、没有任何筛选选项；设为 `true` 后得到 180 个节点，包括完整六组筛选。
- 当前面板使用独立窗口里的原生 RecyclerView：`iu1 → y9y → jhx/jg3 → jhg/vlc`，确认按钮为 `beg / 查看结果`。旧代码只认识语义 ScrollView 和旧五组原生面板，而且关闭多窗口读取，因此始终等不到面板。
- 弹层打开及切换选项的动画期间，首帧可能只有部分分组或选中状态；只等「排序依据」出现仍会偶发误判。必须在已有等待预算内等完整回读，不能把未选中当成成功。

## 修改

仅更新 `runners/android/`，发布版本 0.3.3。

1. 新增当前原生弹层的专用读取器。逐组核对名称、选项文字、辅助功能选中标记、可点击状态与唯一性；六组缺失、重复、状态冲突均不接受。
2. 展开筛选后临时打开多窗口读取；旧语义面板和旧原生面板继续兼容。弹层动画中不完整的回读只在既有 15 秒等待预算内重读，不增加全局超时。
3. 「一天内」和重复的「不限」均绑定到当前分组及实时元素边界；设置后回读全部分组，包括「位置距离」必须不限。
4. 当前原生面板点击「查看结果」应用；保持多窗口可读直到弹层消失且关键词/综合标签核验通过，再恢复正常窗口范围。仍打开的弹层不能被其后面的结果页冒充成功。
5. 所有筛选异常路径恢复窗口范围并清空搜索上下文；等待面板失败带 `stage=search:filter_panel`。
