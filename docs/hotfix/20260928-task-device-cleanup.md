# 任务结束后的浏览器清理与手机归位 Hotfix

状态：隔离开发与本地回归完成；2026-09-28 用户授权提交发布，进入 Extension 0.4.20 / Android Runner 0.2.6 发布流程。实际部署与设备生效以发布回执为准。

- 分支：`codex/hotfix-task-device-cleanup-20260928`
- 基线：`88f5c10c85aece25b014efe4ba4ef7d7254f4da3`
- 基线的 Extension / Android 文件与 `5b87dd4` 的 0.4.19 版本一致，已逐项核对；主工作区旧源码不是本次修复基线。
- 前期测试快照仅生成在本 Hotfix 工作树内，使用 localhost 配置；正式客户包必须从提交的源码重新生成 production 快照。

## 问题与已核实原因

现场截图显示多个 StarVoice 运行页、任务完成十余小时后仍需人工关闭；用户同时要求覆盖报错、手机任务及全部现有任务类型。

1. 无人值守和定向任务按 request + attempt 创建运行页。正常终态已有清理，但当前请求槽被下一任务覆盖后，旧页没有完整历史回收。
2. 旧无人值守运行页会接收全局定向巡查状态，因而显示另一任务的“负面巡查已完成”。多个相同完成卡片不能据此判定重复执行。
3. 远程手动关键词页结束时只写交付状态，没有回收独立运行页。
4. 官方/关注博主任务的 profile 页缺少与负面巡查同等的持久归属；后台先关闭运行页时，页面自身的 finally 可能尚未清理平台页。
5. 已有清理不保证浏览器最后停在平台主页。手机关闭自动化会话也不等于回到应用主页。

上述为代码及隔离 VM 证据；尚未取得截图中各 Windows Profile 的实际版本、任务账本与页面文档身份，不能将每个遗留页归因到某一具体失败分支。

## 本次行为

### 浏览器

- 远程手动关键词任务在生产者停止、待上传数据安全收尾、任务账本终态后关闭自己的运行页；关闭失败保留待清理记录。
- 无人值守页跨 request / attempt 更替时沿用既有退役与冲刷协议。启动、心跳及独立浏览器 alarm 重试已具备完整回执的遗留页。
- 回收前复核 request、attempt、tab、document、待导航 URL、执行锁、在途中继和检查点 outbox。普通错误不能靠无限保留结果页作记录；错误与结果仍保留在原账本中。
- 六种已支持定向 workflow 统一使用现有后台持久平台页归属：负面巡查、关注内容、官方评论、关注博主、官方账号作品发现、手机发现作品补详情。profile 仅匹配原任务的精确账号路径。
- 归位仅在浏览器无活跃任务、执行锁、在途中继或待释放采集会话时进行。每窗口每平台最多一条待归位记录，复用现有主页。
- 当前任务已确认的关键词搜索源页可回主页；用户切走的页面、其他窗口、无法核实归属的来源页不改动。后台重启后，持久 tabId 本身不作为改写源页的权限，只复用或建立主页。
- 手机来源的 `discovered_post_capture` 也走同一后台回收路径。

### 手机

- 当前手机支持的抖音单轮关键词发现（自动/固定/手动分配入口）在安全终态尝试归位，再执行既有会话关闭。
- 等待旧动作实际返回；同一设备会话、有效许可、已识别页面下执行有限返回。最多 15 秒，并为原有 close 预留 31 秒剩余租约。
- 只有首页按钮选中及页面标记读回一致才记录归位成功；会话关闭成功不冒充主页成功。
- 人工停止/接管、USB 失联、租约失效、登录验证、锁屏、未知页面不强制导航。
- 归位或诊断失败不改变原业务统计；可选归位字段不能阻断原结果持久化。物理关闭原有保护保持不变。

## 类型覆盖与保留边界

| 任务类型 | 本次处理 |
| --- | --- |
| 无人值守/一次性关键词、计划关键词 | 精确退役、历史回执重扫、正常终态主页归位 |
| 远程手动批量关键词 | 新增独立运行页回收及归位；真实业务状态由原任务账本决定 |
| 本地手动搜索、作品 URL、批量 URL、博主采集 | 沿用现有任务 Debug/worker 释放；用户原始页保留，不为归位改写采集或手动恢复原页逻辑 |
| 负面、关注内容、官方评论、关注博主、账号发现 | 统一后台持久平台页归属与终态回收；不改采集配置 |
| 手机关键词发现 | 有界安全归位，停止和结果交付规则保持 |
| 手机发现后浏览器补详情 | 包含在定向任务的持久页面回收中 |
| 登录/验证码等 needs_action | 沿用平台处理现场保护，运行页在排空后可回收；不通过跳过保护继续采集 |

手机未支持的小红书或独立手机负面巡查不在此次新增能力范围内。

## 安全约束

- 不改变筛选、翻页、帖子解析、关键词预算、采集次数、服务器派单和数据保存主流程。
- 不删除结果、错误、待上传队列、历史账本；不解除无法证明已经停止的执行锁。
- 旧版本页面没有完整退役/同步证据时不按标题、页龄、域名或“已完成”文字强关。此类历史遗留需先取得对应 Profile 证据，再决定迁移清理。
- 断网或待上传未排空时保留保护和重试，不伪造清理成功。
- 页面在清理中刷新、切换或被新任务占用时重新核验，无法确认即保留。
