## 内容分诊

“情感”右侧增加“意图”，之后增加“相关度”。列表、看板、详情及导出使用一致的中文含义。

| 意图 | 判断原则 |
| --- | --- |
| 分享 | 分享经历、体验、知识、教程或信息 |
| 其他 | 纯营销、改进建议或无法归入其他三类的表达 |
| 投诉/抱怨 | 表达故障、不满、批评、质疑、维权，包含暗讽和反问 |
| 咨询 | 真实寻求事实、方法、价格或购买、使用帮助 |

意图独立于情感和相关性。投诉中的反问不因问号直接当作咨询。历史 `suggestion` 显示为“其他”，不改写原有记录。尚未分类显示“待判断”。意图筛选可多选；全选恢复全部内容，包含尚未判断的意图。导出沿用当前筛选。

相关度显示“明确相关 / 待核实 / 无关”，缺少判断时显示“待判断”。这是分类程度；详情中的 AI 判断置信度只表示模型对结论的把握程度，不将其包装成相关性百分比，也不借用情感置信度。详情保留只读判断依据。

## 哨兵内容拦截

仅对“别克哨兵、至境哨兵、凯迪拉克哨兵、雪佛兰哨兵、通用哨兵”等明确的通用旗下哨兵采集词生效，兼容复合词与同一帖的历史召回词。其他采集任务不应用这道品牌证据门槛。

哨兵帖进入内容分诊须同时满足整体相关性为相关，以及主帖有品牌或车型线索。车型名称、L7 / E5 等简称以及 CT50 这类可结合上下文理解的车型写法都可作线索，不要求重复品牌全称，也不因简称跨品牌就机械拦截。是否属于通用监控范围由主帖整体语境判断；匹配车型线索不代表认定该写法是正式车型名。已有人工相关性纠正优先。关键词、评论、作者昵称和纯话题标签不能代替主帖的车型线索。

名称识别共用一份带来源的字典，覆盖 66 组公司、品牌、服务与车型实体，261 个不重复名称和别名；按强名称与依赖语境的名称拆为 96 条规则。包括三品牌的中英文名称、车型全称与简称，以及中国讨论场景常见的历史车系。大小写、全角、型号内空格及连字符统一匹配，展示引用保留原文写法。完整映射及官方出处见 [上汽通用品牌与车型别名覆盖](2026-09-14-gm-vehicle-alias-coverage.md)。这不是全球历史车型或未来新车的穷尽名单。

已知英文车型的车辆语境可以来自同一主帖的其他可信字段。例如标题只写 LaCrosse、正文反馈哨兵未录像，或“Regal怎么开启哨兵”的自然问句，均可保留整体相关结果，不要求功能词紧挨车型名。评论、纯标签或旧媒体逐字稿不能提供这份语境。

字典未收录的名称不直接判为无关：整体 AI 判断相关，且提供 `entityType=brand/model`、`manufacturer=saic_gm` 与主帖中可逐字核验的完整名称和引用时，同样保留。口语简称、拼音首字母须结合全文归属，不能只凭 BK/KDLK/XFL 等字母认定品牌。泛称、缺失或伪造引用、错误来源不能用作兜底。“上汽通用五菱／SGMW／SAIC-GM-Wuling”的完整名称不会因内部含“上汽通用／GM”而产生本项目品牌证据。旧数据没有这类可核验证据时，不凭空补写模型结论。

证据来源为主帖标题、正文，以及已完成且仍对应当前媒体链接的逐字稿。没有当前媒体对应关系的旧逐字稿、未校验图片文字不作为证据。不启动额外图片识别或媒体转写。

| 主帖示例 | 处理 |
| --- | --- |
| 昂科威Plus哨兵没触发 | 明确车型，整体相关时可进入 |
| 至境L7哨兵体验 | 明确车型，整体相关时可进入 |
| 我的车被剐蹭，哨兵没录像 | 缺品牌车型证据，拦截 |
| 正文无品牌，仅附 `#别克` | 拦截 |
| L7哨兵模式怎么开 / E5驻车监控异常 | 可作车型线索，整体判断相关时保留，不因省略品牌拦截 |
| 理想L7没有录像 | 明确讨论其他品牌且整体判断无关时拦截 |
| 哨兵模式的行业开拓者 | 普通词不能充当车型，拦截 |
| 主帖为 CT50，模型引用截成 CT5 | 相关原帖保留，从原文重新提取完整 CT50 引用 |

主帖已经能识别出名称线索时，模型引用缺失、截断、畸形或旧 `monitoringEvidence.status=needs_review` 不单独否决相关原帖。证据从当前主帖重新提取，展示时不沿用错误引用；表外名称则核验模型给出的逐字实体证据。读取不改写数据库原始判断。AI 整体已经判为无关或不确定的记录，不仅凭一个车型词自动升为相关。

被拦截帖子保留在数据库，不进入内容分诊工作中、归档列表、导出和相关工作区计数。界面保留原有“工作中 / 已归档”两个标签，不增加待核实标签或人工复核流程。关注内容不能绕过哨兵门槛；非哨兵任务沿用既有关注展示行为。

新分类结果随正常 AI 标注写入；历史哨兵记录在读取时同样应用门槛，无需批量改写或重判。模型调用完成后，写入前重读并锁定记录，保护期间发生的人工判断、原文更新和较新的 AI 结果。采集原文与已有处理、归档状态不被这一门槛改写。

## 负面巡查状态筛选

在新建、编辑无人值守计划的“同时巡查近7天负面内容”下增加处理状态勾选。可选项沿用现有九个状态；默认选择八项，排除“已复核-非监控内容”，需要时可主动勾回。

支持全选、取消全选、恢复默认。开启负面巡查时必须至少选一个有效状态；空选或非法状态会阻止预估、继续和保存。关闭负面巡查后不要求勾选状态。

设置保存在 `negativePatrol.triageStatuses`，新建、编辑、复制、预估和确认摘要使用同一选择。修改选择会使旧预估失效。历史计划缺少此字段时使用默认八项；兼容只传启用开关的旧编辑请求，不重置已有选择。

每轮开始时冻结所选状态；编辑只影响下一轮。范围预估、每轮生成候选、实际领取共用相同资格判断。近七天仍以首次采集入库时间计算，重复采集不刷新窗口。归档、实际删除或不可访问、人工已确认无关等既有保护继续生效。
