## 临时浏览器标签页回收

用户观察到补采页面积累。代码复核确认：手机补详情走直接 `tabs.create` 分支，终态回报会先由后台关闭运行页，运行页 finally 中的作品页清理因页面销毁无法可靠执行。现接入已有任务归属登记，由后台先回收作品页、再回收运行页；仅手机补详情的 needs_action 同样关闭页面并保留错误记录，原有其他巡查的人工处理现场策略不变。

关闭前持久化精确归属；关闭失败沿用现有 alarm 重试，未清理成功前不创建下一张补采页。清理校验任务、attempt、命令、页面编号和作品链接，用户手动打开的同作品页、其他 attempt 和被用户导航到别处的页面保留。

Node 18.20.8 与 Node 24.12.0 各 393 项相关测试通过。实际 P0 窗口测试前只有扩展管理页；重试中新增一个执行页和一个作品页，作品页显示约 652 MB；终态后自动回到仅一张扩展管理页。这是原生浏览器可访问性树的前后观测，不是只从代码推断。此前遗留的已完成测试页面显示约 889 MB，已退出该作品页面。生产包未覆盖。

### 第四个真实问题：正常读屏触发 5 秒误超时

11:11:30.199Z（北京时间 19:11:30），`source` 请求在 5002 ms 超时。此前同轮成功读屏已有 5285 ms 与 5514 ms，说明手机界面层级读取有超过 5 秒的正常波动。`waitFor` 原本给读屏 10 秒，复制链接后的直接 `read()` 却沿用 Appium 通用 5 秒限制。整个复制动作当时为 17.628 秒，并非触发 60 秒整步上限。

手机在 19:13 与 19:18 仍由 ADB 识别为 `device`，19:18 macOS USB 设备树也识别同序列号的 Smartisan。Finder 侧栏未显示手机不能作为采集连接断开的证据；本次日志直接证明的是读屏超时，未记录 USB 断开。失败后 19:11:31 已独立确认 session 无效、helper 已停止，pending/quarantine 为 0。

只把 UI 层级直接读取的默认等待统一到 10 秒。调用方更短的超时、父操作取消、60 秒整步限制、每词 10 分钟／每批 25 分钟与租约规则保持有效，没有增加点击或复制的自动重试。新增真实异步传输回归：5.5 秒读屏在旧代码 5 秒处失败，修复后成功；显式短时限、运行中取消、预先取消及大爆炸覆盖保护继续生效。Node 24.12.0 Runner 全套 116 项通过，模块边界仍为 82 个、最大 264 行。
