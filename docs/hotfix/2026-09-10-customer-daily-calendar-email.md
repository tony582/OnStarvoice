# 客户日报、评论区留言状态及邮件 Hotfix

分支：codex/hotfix-daily-comment-status-20260910
基线：e91f93dfed81067b609cc5fa963e9702de6f53c5。
需求依据：本任务给出的9列表格及引用任务《设计负面舆情日报方案》中已确认的客户清单和工作日统计规则。

## 用户可见变化

- 默认进入客户日报；明确的数据看板链接仍可使用。
- 月历基于 React DayPicker 9.12.0（https://github.com/gpbl/react-day-picker），沿用系统已有的中国节假日及调休数据，标注休假、调班及已有日报。电脑侧栏，窄屏收纳；支持键盘导航和切月。
- 新分诊状态 negative_comment，显示“负面-评论区留言”，接入队列、看板、抽屉、批量处理、筛选、操作记录、统计及导出，不自动发布评论。
- 新生成日报逐行列出月初至报表日及 MTD，四类负面分别为冷处理、评论区留言、负面处理流程（negative_feishu）、其他（负面且 unavailable/privacy_unreachable）。休息日留空，内容并入下一个工作日。
- 平台监控量仍为进入客户分诊清单的新增唯一主帖；SDB 再扣已复核非监控内容。18:00 归属、周末/假期合并、热度比较和历史冷处理标记不变。
- 工作日数字可编辑，MTD 自动求和；保存形成新版本，保留原始系统汇总和已发送快照。更新日报沿用现有确认后重新计算的行为。
- 新旧快照分别解释：V1 的“处理中/已处理”不转换成新的分类；新 V2 页面、正文、图片、Excel 和飞书内容使用一致的数据。
- 飞书/邮件发送在页面顶部，不要求勾选、不提供设置入口。收件人仅在设置配置，复用租户 SMTP。邮件正文带汇总和链接，并附 Excel。
- 邮件冻结版本和收件人，同版本幂等；明确失败可主动重试，部分接收/超时/中断不自动重发。现有自动开关继续仅用于飞书。
