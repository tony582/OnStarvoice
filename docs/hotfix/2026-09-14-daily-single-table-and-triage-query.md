# 日报单表与内容分诊加载修复

用户确认日报只保留原上表样式，整张表使用原下方采集数据，MTD 按月去重。此前处理量表与采集量表属于不同集合，不能只替换前几列后混用负面分类。

- 新日报为 `schemaVersion=4` / `daily_collection_v4`。单张九列表直接使用首次入库采集集合及四类负面处理状态，不再计算或显示整月状态变化处理量。保留原采集时间边界、休息日并账、高热负面状态和冷处理证据。
- MTD 读取冻结的月内主帖去重值。人工编辑仅将被修改行的差额加到对应 MTD；无变化保存保持原 MTD，Excel 不用每日 SUM 覆盖它。
- 既有 v1/v2/v3 快照语义保留；可通过纯转换函数基于 v3 冻结 collectionSummary 生成一个新的 v4 版本。旧处理表及人工编辑元数据另存 legacyHandling，原版本、飞书文档及已发邮件不覆盖。
- 意图默认勾选四项，可全选或逐项取消；全选包含尚未判断记录，全取消为零结果（导出同口径）。列表与看板失败显示错误和重试，25 秒结束加载等待；看板查询并发限制为 2，避免同时请求列表和看板。
- 线上故障根因：16,553 字的车型名称正则在 PostgreSQL 首次编译/规划时耗时很长，随后高估查询成本又触发昂贵 JIT，内容分诊和侧栏计数占用 general 连接，其他接口排队失败。
- 将同一别名集合的公共上下文提取并拆为 8 组 SQL 正则，保留原 JavaScript 判断及引用提取。50,928 条 JavaScript / 旧 PostgreSQL / 新 PostgreSQL 样本结果一致。
- 生产只读基准：原完整查询超过 8 秒，优化后关闭 JIT 的规划约 169ms、执行约 590ms。含证据判断的分诊/工作台读查询进入独立 reporting 预算，以只读事务局部关闭 JIT，并设置排队和语句时间上限，不影响一般查询或控制任务连接预算。

所有展示、图片、Excel、文本及飞书输出使用同一 v4 统计；此次不触发历史帖 AI 重判或报告重发。
