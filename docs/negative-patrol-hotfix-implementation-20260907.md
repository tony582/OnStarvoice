## 已实施变更

### 1. 预览与下发使用当前真实情感

- 预览按当前保存的人工情感覆盖计算有效情感；人工中性、正面不进入负面候选，人工负面可以进入候选。
- 人工负面不再被历史 AI 相关性或自动业务可见性误排除；人工无关、归档、官方内容、原帖失效等明确状态仍阻止下发。
- 人工情感格式异常时不回退为历史负面，也不会显示为“人工负面”。
- 待复核误报在已有人工负面确认时显示提示但允许下发；没有人工负面确认时暂缓。
- 时间范围使用 `Asia/Shanghai`，开始日包含、结束日包含到次日零点前；只使用有效原始发布时间和 `published_ts`，不以创建时间替代。
- 预览与创建共用资格规则。创建在同一事务内按所选记录 ID 再验证，状态已变化的记录会被明确拒绝。
- 候选使用稳定游标分页；单批最多 100 条。前端只有 `canDispatch === true` 才允许选中。
- 多后台页提交使用 Web Locks 串行“检查并创建”，每个请求按独立 requestKey 保存恢复快照；未知结果只复用原请求，完成后只删除该请求的记录。

### 2. 平台页面按任务身份自动收口

- Extension 为负面巡查创建平台页时，持久化 command、request、attempt、session、tab 和 URL 的完整所有权。
- 成功、失败、取消等可确认终态先持久化有界终态回执，再向服务器确认，最后关闭该任务拥有的平台页、执行锁和 runner 页。
- 验证码、登录失效等 `needs_action` 状态保留平台页，供人工继续处理。
- 关闭失败会保留回执并由监督心跳重试；只有明确确认 tab 已不存在才视为完成，读取状态失败会保守重试。
- 平台页使用带唯一轮次标记的占位 URL；即使平台注册写入与首次关闭同时失败，也会保留有界清理记录并在启动或定时唤醒后继续回收。回收前会重新核对平台、帖子 URL 和 externalId，避免误关复用 tab 或同平台其他帖子。
- 服务器终态通知即使到达时本地 current 状态已经消失，也会按精确 requestId、attemptId 和平台注册恢复原 command 身份，关闭旧轮页面；任何资源未清理完成都不会向服务器 ACK。
- 服务器停止与完成同时发生时，使用精确 stop ACK 处理被停止取代的完成回执；不会让旧完成结果覆盖停止，也不会误删新一轮执行。
- 针对 v0.4.5 已存在的本地孤儿状态，只有服务器 ledger 已终态、任务身份完全一致且确认没有同轮 runner、平台页和执行锁时才自动收口。

### 3. 下发与后处理限流

- 负面巡查拆为服务端逐帖队列；Agent 每次只领取 1 条，完成或释放后再领取下一条。
- 全局最多 2 条、同租户最多 1 条负面巡查处于 admission，占用首条时至少间隔 10 秒。
- 旧版多帖打包任务禁止继续领取；未领取的迁移为逐帖队列，已领取的发送精确停止并等待回执。
- 数据库请求分为 critical、general、reporting 容量；等待、语句和锁都有上限。预览、停止和完成在容量不足、超时或死锁时返回 `503 + Retry-After`。
- 后台列表轮询改为单飞请求，页面隐藏时暂停，失败后退避，手动刷新合并到当前请求。
- 概览查询关闭 JIT、设置只读超时并做短时合并缓存，避免重复重查询。
- 评论持久化和 AI 精炼使用 PostgreSQL 全局处理租约；历史评论自愈每分钟最多处理 25 条。
- 记录观察写入按 tenant、record、capture item attempt 幂等，并限制单次 observation 体积和总数。

### 4. 停止、重分配与旧任务恢复

- 父任务停止、子任务完成和重分配使用同一 orchestration control lock，锁顺序统一为父任务优先。
- 已交付到设备的子任务不会仅因服务器命令失效就被直接标成已停止；必须等待精确 stop 回执或终态通知。
- `needs_action` 子任务只要仍带 `stopPending` 就继续计入父任务待停止数。stop 失败、过期或节点暂不可用会保留停止屏障并转入终态通知恢复；只有精确成功回执或精确终态通知 ACK 才清除标记并结束父任务。
- 普通关注账号、关注博主、官方账号发现与负面巡查使用同一套定向 attempt 身份约束；缺少执行轮次时不发送客户端必然拒绝的 stop。
- 已停止的 parent/item 会阻止继续领取和自动重试；待设备确认期间父任务保持 `waiting_device`。
