# 系统架构与稳定版交接手册

本文面向需要接手 StarVoice 研发、实施或运维工作的成员，描述当前稳定基线的真实组成、边界和核心链路。

## 1. 稳定基线

| 项目 | 当前值 |
|---|---|
| 主分支 | `main` |
| Extension | `0.3.67` |
| 最新数据库迁移 | `050_ticket_comment_record_link.sql` |
| 生产域名 | `https://voice.minilife.online` |
| 生产服务端口 | `3002` |
| PM2 应用 | `onstarvoice` |
| 生产目录 | `/opt/onstarvoice` |
| 生产数据库 | `onstarvoice` |

版本号只能证明代码快照，不证明某个客户浏览器已经 Reload 或安装了该版本。排查客户问题时，需要同时核对 Extension 页面显示版本、Agent 心跳上报版本、生产服务版本和任务发生时间。

当前“稳定基线”是交接和回归锚点。调度中心、多 Agent 失败接力、无人值守、平台风控识别和依赖平台 DOM 的采集仍属于 Beta 或需客户环境持续验收的能力，不能因为版本号稳定就省略目标账号、目标页面和目标 Agent 的实测。

## 2. 组件职责

### 2.1 Browser Extension

Extension 是实际访问平台页面和执行采集的主体，负责：

- 识别小红书、抖音等支持页面；
- 读取列表、详情、作者和评论；
- 管理本地任务账本、步骤、检查点、恢复信息和采集锁；
- 显示暗色任务运行页、实时进度、停止和隐藏操作；
- 向云端上报 Agent 心跳、任务快照和事件；
- 领取并执行云端 `create`、`resume`、`stop` 等指令；
- 把采集结果通过同步 API 写入当前租户。

Extension 不能在电脑关机或浏览器彻底退出时运行，也不能把一个浏览器的登录态迁移到另一个 Agent。

### 2.2 Node.js / Express 服务

服务端是业务事实中心，负责：

- 用户登录、租户、成员和角色权限；
- 激活码、环境绑定、Agent Token 和节点身份；
- 内容、评论、作者、快照、工单和处理记录；
- 云端任务、命令、尝试、工作项和审计事件；
- 多 Agent 编排、无人值守排期和失败项重新分配；
- 负面帖子、关注博主、官方账号评论巡查；
- AI 相关性筛选、舆情研判、深度分析、评论精炼；
- SMTP 邮件和系统内人工介入事件；飞书 Webhook 仅是历史预留，当前代码未实现发送；
- 管理后台、独立看板和媒体文件的静态服务。

### 2.3 PostgreSQL

PostgreSQL 保存业务状态和审计历史。重要原则：

- 租户 ID 是业务数据隔离主键之一；
- Agent Token 只保存哈希；
- 任务快照和舆情互动快照采用追加式历史，不能用新数据覆盖历史；
- 当前态与历史态分开：任务当前态在 Task/Attempt，过程在 Event/Snapshot；
- 工单、评论、内容、巡查记录必须通过明确关联保留来源。

### 2.4 管理后台与独立看板

`web/admin` 是日常运营后台，包括：

- 指挥中心与舆情工作台；
- 内容分诊、评论分诊、工单和误判反馈；
- 关注博主、官方账号评论巡查；
- 调度中心与执行节点；
- 社交账号与每日负载；
- 数据底座、舆情分析和报告。

`web/dashboard` 是独立数据看板。现有生产发布脚本不会自动构建它，发布 Dashboard 改动时必须单独构建和同步。

## 3. Agent 与设备模型

### 3.1 真正的调度单元

一个浏览器 Profile 对应一个 Agent。以下都可以是独立 Agent：

- 同一电脑上的 Chrome 和 Edge；
- 同一电脑上两个相互独立的 Chrome Profile；
- 不同电脑上的浏览器；
- 同一浏览器品牌但使用不同用户数据目录的实例。

同一 Profile 打开的多个普通窗口共享 Extension 存储、Agent 身份和采集锁，不能当成多个 Agent。

### 3.2 “设备”只是可读分组

浏览器无法稳定、合规地读取唯一物理机器 ID，所以后台的“所属设备”主要用于客户识别和分组。调度、在线判断、平台能力和任务队列都基于 Agent，而不是物理电脑名称。

### 3.3 在线判断

- Agent 定期发送心跳；
- 连续约 2 分钟没有心跳，后台视为离线；
- 浏览器进程存在不代表 Extension 正常；
- Extension 面板打开也不等于 Agent 正在领取任务；
- 在线只说明心跳可达，不说明平台登录态、页面能力或任务一定成功。

后台应同时展示：

1. 设备心跳：浏览器 Agent 是否在线；
2. 任务心跳：执行循环是否仍在运行；
3. 业务进展：关键词、帖子、评论或保存数量是否真实推进。

## 4. 租户与认证边界

### 4.1 后台用户

后台用户通过登录会话访问系统，服务端结合 `x-tenant-id` 检查用户对目标租户的成员关系和角色。平台管理员能力不能等同于普通租户管理员。

### 4.2 Extension Agent

Extension 激活后，服务端根据激活凭证和环境绑定解析租户并签发 Agent Token。服务端不信任 Extension 任意提交的租户 ID。

Agent Token 只允许：

- 上报自身心跳和任务；
- 领取分配给自身的命令；
- 回传自身命令结果；
- 使用被允许的采集与同步能力。

它不能登录管理后台，也不能读取其他 Agent 或其他租户的数据。

### 4.3 数据复制与测试租户

生产租户复制到测试租户时必须：

- 先创建可恢复备份；
- 重写租户外键和唯一键；
- 不复制用户会话、Agent Token、激活码明文或生产命令队列；
- 重新绑定测试 Agent；
- 明确是否复制媒体、快照、工单和 AI 分析；
- 防止测试任务回写生产租户。

## 5. 核心数据流

### 5.1 本地手工采集

```text
用户在平台页面启动采集
  → Extension 建立本地任务和采集锁
  → 解析列表或详情
  → 可选 AI 前置相关性筛选
  → 可选逐篇增强、作者和评论采集
  → 本地保存结果
  → /api/sync 或 /api/sync/batch
  → 服务端幂等写入内容、评论、作者和快照
  → 后台 AI 异步研判与评论精炼
```

### 5.2 云端一次性任务

```text
后台创建任务
  → 服务端创建占位 Task + Command
  → Agent 心跳领取 Command
  → Extension 创建同一稳定 ID 的本地任务
  → 回执 claimed
  → 真实运行上报 running / progress / snapshot
  → 同步采集结果
  → 工作项聚合为 completed / partial / failed
```

### 5.3 多 Agent 编排

```text
父任务 + 工作项列表 + 候选 Agent
  → 服务端做确定性均衡切片
  → 创建 Allocation 和 Agent 子任务
  → 各 Agent 独立领取与执行
  → 工作项逐项成功、跳过、重试或失败
  → 父任务聚合状态
  → 可对失败工作项重新分配
```

### 5.4 无人值守计划

保存计划不等于立即执行。计划包含平台、关键词、筛选、日期或每日时间、随机延迟和分配信息。到达排期后才生成真实任务；若上一次仍在运行，当前策略跳过重叠执行。

### 5.5 负面帖子跟踪

负面候选被定向采集后，系统保存内容、评论、可用状态和互动快照。后续巡查通过同一作品标识更新当前数据并追加快照；帖子删除或不可用会记录业务状态。转为工单后，巡查、评论和快照关联仍须保留。

## 6. 状态事实来源

| 信息 | 首选事实来源 |
|---|---|
| Agent 是否在线 | 最近心跳时间 |
| Command 是否领取 | Command 状态和领取时间 |
| 任务是否真的运行 | Attempt 心跳、运行事件 |
| 完成了多少关键词/帖子 | Work Item 状态聚合 |
| 是否保存到后台 | 同步响应、记录 ID、任务写回事件 |
| 是否已删除 | 详情页明确不可用信号和内容可用状态 |
| 是否发生风控 | 明确验证码、安全验证或平台风险代码 |
| AI 是否介入 | AI 请求/结果状态、筛选事件，不看页面停留时间 |

不要用单一的 100% 进度条判断任务成功，也不要因为浏览器打开了一个看似相似的帖子就认为目标工作项完成。

## 7. 服务启动时的后台任务

服务启动后除监听 HTTP 外，还会：

- 初始化并执行未应用数据库迁移；
- 初始化媒体目录；
- 启动无人值守与编排排期；
- 把长期未完成的舆情分析标记为失败；
- 延迟恢复待处理评论的 AI 精炼；
- 延迟补齐封面与本地图片；
- 持续运行评论 AI 精炼循环。

因此重启后短时间内数据库和 AI 队列可能出现集中处理。生产重启前应确认队列规模和外部 AI 限额。

## 9. 不变量

任何修改都应保持以下不变量：

1. 同一租户、Agent 和稳定任务 ID 的重试不能制造重复任务。
2. 任务继续从服务端确认的工作项/检查点开始，不能仅靠页面当前位置猜测。
3. 工作项只能归属一个有效执行 Agent；重新分配必须留下历史。
4. Extension 接收的命令必须校验 Agent、租户、能力和任务目标。
5. 目标作品标识不一致时不得写回原工作项。
6. 快照只追加；历史数据不能被后续采集覆盖。
7. 原始采集成功不应因 AI 超时而回滚。
8. 删除/无结果/范围外是业务结论，明确验证码/安全验证才是人工介入。
9. 工单必须保留内容、评论、巡查和快照来源。
10. 生产发布前必须备份；迁移、重启和验证是独立步骤。

## 10. 修改入口建议

| 需求 | 优先检查 |
|---|---|
| 平台页面采集异常 | Extension 内容脚本、页面适配器、运行事件 |
| 任务重复或续跑位置错误 | 本地任务账本、稳定 ID、Work Item、Attempt |
| 后台在线状态错误 | Agent heartbeat、版本、离线阈值 |
| 多 Agent 分配不均 | orchestration/allocation 服务和契约测试 |
| 负面巡查结果缺失 | negative patrol 路由、内容标识、快照和写回 |
| 官方评论巡查日期错误 | 账号主页发现、详情页发布日期确认 |
| AI 没有介入 | prefilter 模式、队列、外部 API、超时和事件 |
| 生产页面未更新 | 实际构建目录、同步范围、PM2 和 Nginx 缓存 |

后续详细状态与发布操作分别见 [任务编排与状态模型](任务编排与状态模型.md) 和 [开发运行与生产发布手册](开发运行与生产发布手册.md)。
