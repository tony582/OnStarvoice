## 文档维护规则

1. 任何新增业务状态必须同步更新状态模型、API 文档和用户可见文案。
2. 新增数据库迁移时，更新 [数据库与迁移说明](数据库与迁移说明.md) 的迁移索引与回滚边界。
3. 新增 Extension 能力时，同时更新源码、`extension-build/` 交付快照、Manifest 版本和 Extension 交接文档。
4. 修改部署脚本时，更新生产发布手册；不要用“滚动发布”“自动回滚”等词，除非脚本真实实现。
5. 发布前的漏洞数量、测试数量、依赖版本和生产状态都是时效信息，文档必须写扫描或验证日期。
6. 文档示例不得包含真实 API Key、数据库密码、激活码、Agent Token、会话或客户隐私数据。
7. 旧文档如果不再适用，应在开头标明历史范围或改为指向当前文档，不能让两个互相冲突的说明同时存在。
